# Gentactix 核心推演引擎最终规格书

## 确定性世界事务、像素硬约束、双场与拉格朗日实体

> 文档编号：GTX-CORE-SPEC-FINAL-2.0  
> 文档性质：目标架构契约，不代表现有实现已经完成迁移  
> 适用范围：推演核心、服务端适配层、快照与前端发布链路  
> 规范原则：只声明目标系统应当成立的规则，不从旧实现反推架构，不继承未经声明的数值参数

## 0. 规范效力与参数主权

### 0.1 规范关键词

- **必须**：实现不可缺少、不可绕过的契约。
- **禁止**：任何模块不得以性能、表现或兼容为理由违反的规则。
- **可以**：满足前置契约后允许选择的实现方式。
- **候选**：尚未被证明适用于全部场景的算法或优化，不得提升为全局公理。

### 0.2 四个规范层次

1. **世界契约**：什么是权威状态，谁可以提交状态，怎样保证确定性。
2. **物理契约**：几何、实体、场和事件分别表达什么，怎样保持合法与守恒。
3. **算子契约**：一个数学算子在什么条件下有效，失败时怎样报告。
4. **实现契约**：内存、并行、SIMD、缓存、网络和渲染如何实现上述语义。

下层实现不得反向修改上层语义。性能优化不得改变事件结果、实体身份、守恒关系或硬约束结论。

### 0.3 参数分类与唯一所有者

任何数值参数必须归属于以下一类，并在其所有者处显式声明：

| 参数类别 | 所有者 | 示例 |
| :--- | :--- | :--- |
| Doctrine 参数 | 本规格 | 核心战术网格基准尺度、默认原子 Subtick、规范状态顺序 |
| 场景参数 | 场景定义 | 世界范围、网格行列数、初始实体与环境 |
| 模型参数 | 对应物理或行为模型 | 碰撞半径、容量、速度、阈值、弹药系数 |
| 实现参数 | 可替换实现配置 | Tile、线程数、缓冲区容量、SIMD 路径 |

必须遵守：

- 禁止把某一场景的世界尺寸、网格行列数或实体数量写成通用内核常量。
- 禁止把某一模型的半径、容量、阈值或弹药系数写成所有模型共享的常量。
- 禁止把某一机器的缓存尺寸、任务场数量、性能耗时或帧率写成正确性条件。
- 通用算子不得包含来源不明的魔法数。所有数值必须具有名称、单位、类型、有效范围、所有者和修订号。
- 派生数值必须由公式计算，不得另写一份可能失配的常量。
- 未声明参数属于规格错误，不得通过猜测默认值继续执行。
- Doctrine 参数只能由本规格修改，场景、模型和实现层不得覆盖。

## 1. 核心法条

### 1.1 世界只能经事务推进

设 Tick 开始时的已提交合法状态为 $S^n$，最终状态为 $S^{n+1}$。世界只能由唯一 Tick 事务编排器完成：

```text
S^n → 意图与提案 → 约束与事件结算 → 校验 → S^(n+1)
```

禁止玩家接口、自主系统、战斗事件、动画或网络回调分别直接改写同一份权威状态。

### 1.2 像素容器承载物理，不承载战争意志

像素容器及其关联算子负责：

- 表达空间几何、材质、障碍、容量与环境状态；
- 保存或计算物理场及其守恒账本；
- 提供派生空间数据和有效性证明；
- 接受、限制、拒绝或报告运动与作用提案。

像素容器不得自行决定任务、阵营目标、命令权限、士气判断或战术意志。容器不是智能体；场算子也不是指挥官。

### 1.3 三类信息不得相互冒充

| 表示 | 负责内容 | 不得承担的内容 |
| :--- | :--- | :--- |
| 拉格朗日实体 | 身份、精确位置、编制、健康、装备、库存、关系 | 用逐实体全局扫描冒充所有空间场 |
| 欧拉场 | 密度、烟雾、暴露、威胁、超压、破片通量等空间聚合量 | 在仍需身份时抹掉来源与目标 |
| 离散事件 | 射击、命中、爆炸、移交、破坏等有来源或顺序的作用 | 把每次精确作用永久堆积为网格状态 |

若投影进场后仍需回答“是谁、从哪里来、作用于谁、按什么顺序”，则必须保留实体或事件，不得提前聚合。

### 1.4 冲突优先级

```text
世界有效性、守恒与确定性
  > 地形和实体硬约束
  > 命令权限与信息可见性
  > 任务进展
  > 运动平滑与视觉表现
```

宁可停止提案并报告不可行，也不得为了持续推进或画面平滑而提交非法状态。

### 1.5 禁止静默伪造合法

禁止通过以下方式掩盖失败：

- 用未声明的 `epsilon` 把退化问题伪装成正常解；
- 用无模型依据的 `clamp` 把越界位置伪装成合法位置；
- 用 `saturating_add` 隐藏权威账本或物理场溢出；
- 清空尚未结算的事件、命令或持久效果；
- 丢弃错误码后继续发布状态；
- 同时走两条结算路径以避免处理语义冲突。

物理模型本身规定的饱和、边界或截断可以存在，但必须作为模型语义显式声明，而不是异常处理手段。

## 2. 状态所有权与生命周期

### 2.1 `WorldState`：权威状态

`WorldState` 是可存档、可回放并进入完整权威指纹的唯一事实来源，至少包括：

- `ClockState`：Tick 序号、逻辑时间、调度队列；
- `TerrainState`：高程、材质、结构、持久地形变化及修订号；
- `EntityState`：实体身份、位置、姿态、健康、编制与关系；
- `InventoryLedger`：人员、武器、弹药、装备、补给和地面实物；
- `CommandState`：命令、权限、任务、控制关系；
- `KnowledgeState`：阵营知识、感知记录和战争迷雾事实；
- `PersistentFieldState`：烟雾、持续污染及声明跨 Tick 的环境状态；
- `ScheduledEventState`：装填、延迟作用和其他长期计划；
- `RandomState`：所有权威随机流的状态或可重建位置；
- 持久小数账本及模型明确要求保留的连续状态。

### 2.2 `DerivedState`：可重建状态

派生状态只用于加速或发布，包括：

- SDF、法向、通行张量和空间邻域；
- 门户拓扑、任务场和威胁场缓存；
- 光栅化查找表与空间核；
- 脏区索引、快照编码和渲染缓冲。

每个缓存必须携带：

```text
CacheKey
Dependencies: [(state_kind, revision)]
BuilderVersion
ValidityDomain
```

依赖修订不匹配、构建器版本不匹配或超出有效域时，缓存必须重建或返回 `Stale`，不得继续作为有效输入。

### 2.3 `TickScratch`：单 Tick 工作区

`TickScratch` 只包括：

- 意图缓冲与仲裁结果；
- 运动提案、约束结果和提交缓冲；
- 即时事件缓冲与事件效果覆盖层；
- 瞬态超压、破片及求解工作区；
- 本 Tick 的发布清单和诊断信息。

Tick 结束后必须证明工作区不再影响下一 Tick。该规则只适用于瞬态数据，禁止顺带清除持久烟雾、长期事件、库存小数、装填状态或其他权威连续状态。

### 2.4 单一事实来源

- 单兵实例化后，单兵账本是人员数量、健康和装备的权威来源；单位汇总值只能是派生聚合。
- 一件实物在同一逻辑时点只能有一个权威所有者或位置。
- 地形修改只能产生一个权威修订序列。
- 同一实体位置只能有一个 Tick 内提交点。
- 缓存、显示快照和单位汇总不得反向覆盖权威状态。

## 3. 空间与像素流形契约

### 3.1 连续坐标

连续世界坐标统一使用米制强类型，网格索引统一为 `(r, c)`：

- `r` 沿世界 `y` 方向；
- `c` 沿世界 `x` 方向；
- 连续位置与离散索引不得使用同名无单位类型混传；
- 经纬度、地图投影和屏幕坐标只能由适配层转换；
- 角度、时间、距离、面积和密度必须具有明确单位。

### 3.2 核心战术网格基准

核心战术像素流形的物理格边长是 Doctrine 参数：

```text
CANONICAL_TACTICAL_CELL_SIZE = 2^3 m = 8 m
```

必须遵守：

- 核心战术几何在 `x` 与 `y` 方向均使用该格边长；
- 场景、模型和实现配置不得将其替换为其他数值；
- 所有距离、面积、邻域、核半径和物理通量必须以该几何为准推导；
- 渲染、缩略图和非权威预览可以采用其他采样尺度，但不得反向参与权威物理结算；
- 若存在其他权威空间层级，必须显式声明与核心战术几何的转换、守恒和修订关系。

### 3.3 二进制坐标与索引

使用二进制定点世界坐标时，若小数位为 `F`，核心网格索引及单元内偏移可以计算为：

```text
cell_x = fixed_x >> (3 + F)
cell_y = fixed_y >> (3 + F)
offset_x = fixed_x & ((1 << (3 + F)) - 1)
offset_y = fixed_y & ((1 << (3 + F)) - 1)
```

必须使用算术右移处理有符号坐标，并在转换前检查世界边界。使用浮点坐标时：

```text
c = floor((x - origin_x) / 8 m)
r = floor((y - origin_y) / 8 m)
```

除以 8 等价于乘以可精确表示的 $2^{-3}$，但坐标减法、世界原点、舍入模式和累计运算仍须遵守数值误差契约；不得把一次精确缩放夸大为全部浮点运算零误差。

### 3.4 `GridGeometry`

```rust
pub struct GridGeometry {
    pub id: GeometryId,
    pub origin_m: [Meter; 2],
    pub rows: GridExtent,
    pub cols: GridExtent,
}
```

核心战术几何的格边长由 Doctrine 提供，不由场景重复填写。几何构建时必须验证：

- 原点有限，行列数非零且能够覆盖声明的世界范围；
- 世界范围等于 `origin + [cols, rows] × 8 m`；
- 越界返回 `OutsideBounds`，不得默认吸附到边缘后继续当作真实位置；
- 不得仅因索引相同，就在不同原点、范围或层级的几何之间直接互读数据。

标准战术配置采用 `1024 × 1024` 单元，其世界覆盖范围必须计算为 `8192 m × 8192 m`。采用其他行列数时，必须由场景显式声明，不得虚构相同世界范围。

### 3.5 多网格与二进制层级

系统可以只存在核心战术网格，也可以存在多个独立或层级网格。若存在宏观父层级，其格边长采用 $2^8\text{ m}$；此时与核心战术网格的空间比为 $2^5$。

任何父子关系必须显式声明：

- 世界覆盖范围与父子映射；
- 有效掩码和 Halo；
- 创建、激活、休眠和销毁条件；
- 跨网格沉积、采样和守恒转换；
- 各网格的修订依赖。

没有声明父子关系的网格不得被自动解释为父网格或子网格。宏观层级是否启用由场景决定，不得无边界复制全场多通道细网格。

### 3.6 像素流形的数据拆分

逻辑上的像素流形由以下部分组成，不要求合并为单一巨石结构体：

- `TerrainState`：权威高程、材质、结构和持久破坏；
- `GeometryCache`：由地形构建的 SDF、法向和通行数据；
- `PersistentFieldSet`：具有跨 Tick 生命周期的环境场；
- `SparseCellLedger`：地面实物、尸体或局部稀疏记录；
- `TickFieldWorkspace`：只在本 Tick 存在的物理工作区。

统一的是坐标、修订、生命周期和提交契约，不是所有数据的所有权、存储类型或业务边界。

### 3.7 插值与沉积

- 连续标量场的 `gather` 可以使用双线性插值，但必须声明边界条件。
- 材质、障碍、合法掩码和离散类别禁止模糊插值。
- `splat` 必须声明核、支撑范围、归一化与守恒性质。
- 梯度必须声明差分格式、有效区域和不可达处理。
- 跨障碍或跨不连续材质的平滑不得把两侧非法混合。

## 4. 类型化场契约

### 4.1 `FieldDescriptor`

每个场必须声明：

```text
FieldId
GeometryId
Unit
ValueType
AggregationAlgebra
Persistence
BoundaryCondition
ConservationRule
Revision
ValidityDomain
```

缺少上述语义的裸数组不得进入权威物理结算。

### 4.2 聚合代数

| 场类型 | 候选代数 | 必要条件 |
| :--- | :--- | :--- |
| 密度、数量、破片通量 | `Sum` | 单位一致、核权重明确、检查溢出 |
| 冲击波峰值 | `Max` | 模型明确采用峰值包络 |
| 多次冲击疲劳 | `Lp` 或模型规定代数 | 给出指数、量纲与生理依据 |
| 导航距离 | `MinPlus` | 代价非负性及不可达值明确 |
| 烟雾 | 模型规定的累积与透射函数 | 区分光学厚度、浓度与能见度 |

代数属于物理语义，不是容器优化选项。`Sum` 的守恒测试不得错误套用到 `Max`、`Lp` 或 `MinPlus`。

### 4.3 场与实体的四种交换

- `deposit`：实体把声明的物理量沉积到场；
- `gather`：实体从有效场读取局部量；
- `splat`：事件或核把作用写入工作场；
- `resolve`：按事件、实体或账本规则结算场的作用。

每次交换必须明确单位、时间切片、代数、来源和修订。禁止同一作用既通过场又通过事件重复结算。

## 5. 实体、意图与运动提交

### 5.1 实体权威身份

每个实体必须具有稳定唯一 ID。单兵或装备实体至少能够关联：

- 编制与指挥关系；
- 位置和姿态；
- 健康与生理状态；
- 武器、装备和库存；
- 当前知识与可见信息；
- 可接受意图的权限范围。

SoA 是热点数据的实现方式，不改变身份和账本关系。

### 5.2 每实体每 Tick 唯一运动意图

命令、直控、自主策略和其他系统只能提交 `IntentCandidate`。仲裁器必须产生至多一个：

```text
MotionIntent {
    entity_id,
    source,
    objective,
    model_revision,
    knowledge_revision
}
```

仲裁必须稳定、可审计，并记录选择或拒绝原因。禁止通过保存位置、运行另一系统、再恢复位置的方式制造写入优先级。

### 5.3 运动提案不是位置提交

`ProposeMotion` 只生成期望速度或位移。后续必须依次经过：

1. 路径与高速运动检查；
2. 地形、SDF 和边界约束；
3. 容量预约；
4. 实体接触与邻域约束；
5. 最终合法性验证；
6. 唯一 `CommitMotion`。

任何阶段均可返回安全停止、修正提案或不可行诊断，但不得绕过剩余硬约束。

### 5.4 SDF 投影的有效域

局部投影可以表示为：

```text
x' = x + (r_body - d(x)) n(x)
v' = v - (v · n) n
```

只有满足以下条件才可使用：

- SDF 与当前地形修订一致；
- 查询点位于法向和距离的有效域；
- 实体半径与模型匹配；
- 整段运动路径已检查，不能只检查终点；
- 修正后位置仍通过全部约束。

单遍投影不是绝对防穿模证明。高速隧穿、无效法向、非法初态和多重接触必须显式处理。

### 5.5 保守位移信赖域

在合法初态、完整邻域和同步线性子步等前提成立时，可以使用：

```text
b_i = 1/2 × min_j(d_ij^n - D_hard - δ)
Δx_i = p_i × min(1, b_i / ||p_i||)
```

其中所有安全距离和裕量必须由模型声明。若邻域不完整、初态非法、存在外部位置写入或运动假设不成立，该公式不得声称提供安全保证。

该算子只限制位移，不保证任务进展、全局可达或无死锁。

### 5.6 容量与接触

- 容量必须区分人员、体积、装备或其他模型维度，不得使用无量纲通用人数常量。
- 容量预约必须具有稳定顺序和明确的冲突结果。
- 单元容量不等于连续实体接触求解，不能仅凭容量计数宣称不会重叠。
- 无法完成预约或接触约束时，必须返回 `Blocked` 或 `Infeasible` 及原因。

## 6. 双场与策略边界

### 6.1 双场的职责

- 任务场提供长程目标、通行代价和方向信息；
- 威胁场提供危险、暴露、方向矩或其他感知聚合；
- 实体与策略层把场信息转化为意图；
- 硬约束层决定意图能否形成合法运动。

场不直接拥有卧倒、撤退、包抄、恢复任务或切断命令的权限。

### 6.2 任务场共享

任务场可以按以下依赖键共享：

```text
ObjectiveKey
TraversalModel
CostModel
KnowledgeDomain
GeometryRevision
```

共享的前提是控制问题及输入等价，而不是实体数量相近或希望减少内存。活跃任务场数量由实际依赖与预算决定，不设未经验证的固定语义上限。

### 6.3 威胁方向与符号

每个威胁场必须声明“数值越大越危险”或相反约定。若危险标量为 $I(x)$，常见排斥方向为 $-\nabla I$。局部梯度、最大威胁方向和威胁质心是不同统计量，不得混用。

有限方向输运、门户图和局部视界传播都是候选算子。采用近似时必须声明方向离散、遮挡误差、更新频率和适用条件，不得冒充任意情况下的精确可见性。

### 6.4 保下降投影

给定任务梯度 $g=\nabla T$ 和候选向量 $w$：

```text
q = ||g||²
b = v²q - ε_p
P_g(w) = w - ([gᵀw - b]₊ / q)g
u = P_g(w) - v²g
```

必须满足：

- $q>0$ 且任务场在查询点有效；
- $v$、$\epsilon_p$ 及其单位由模型声明；
- 输入场与当前几何和知识修订兼容；
- 投影结果仍需经过运动硬约束。

$q=0$、不可达或陈旧输入必须返回 `Degenerate`、`Unreachable` 或 `Stale`。禁止加入任意 epsilon 后回退原始斥力并声称完成了保下降投影。

该算子只保证其声明的局部代数性质，不保证全局到达、自动包抄、无局部极小值或无死锁。

### 6.5 零点、朝向与行为

- 零合力只表示平衡点，不能自动称为鞍点或突变。
- 零方向矩不存在唯一数学朝向，可以输出无朝向、使用上一有效朝向或引入显式记忆状态。
- 若引入平滑、记忆或历史感知，其状态必须纳入权威状态或明确的派生缓存。
- 单一威胁阈值不得由物理内核强制触发卧倒、撤退、任务断路或意志恢复；这些属于可替换行为模型。

## 7. 离散事件与精确结算

### 7.1 `EventBuffer`

即时事件属于 `TickScratch.EventBuffer`。每个事件至少包含：

```text
EventId
EventKind
ResolvePhase
SourceEntityId
TargetKey
ModelRevision
Payload
StableSequence
```

需要跨 Tick 的事件必须转入权威调度状态，不得长期滞留在即时工作区。

### 7.2 稳定排序

默认稳定排序键为：

```text
(resolve_phase, target_key, source_entity_id, source_event_id, sequence)
```

若模型需要其他排序，必须在事件类型契约中声明，并保证排序不依赖哈希表遍历、线程完成顺序或内存地址。

### 7.3 唯一终态

每个进入结算的事件必须且只能进入一个终态：

```text
Resolved
Rejected
DiscardedByRule
ConsumedByField
```

终态必须带原因代码。未处理、被静默覆盖或残留到下一 Tick 的即时事件均视为事务失败。

### 7.4 精确作用与聚合作用

- 精确武器命中、来源伤害、装备移交和定向 LOS 可以保留离散事件与射线遍历。
- 可聚合的爆炸环境作用可以构建瞬态场，再由实体采样结算。
- 需要来源身份的伤害必须保留事件来源，不得只读取匿名标量。
- 同一弹丸、命中或爆炸作用必须声明唯一结算入口，禁止直接伤害与场伤害重复执行。

### 7.5 事件效果与提交

事件结算在 Tick 内效果覆盖层上工作。后续事件若依赖先前效果，必须读取包含先前已接受效果的视图。所有效果在统一提交阶段写入权威状态；任何校验失败都不得形成部分不可解释的外部发布。

## 8. 密集火力、地形与账本

### 8.1 瞬态杀伤工作区

瞬态超压、破片和相关工作数组只属于当前 Tick：

- 峰值超压可以采用 `Max`；
- 疲劳累积必须采用模型声明的代数；
- 破片通量采用 `Sum` 时必须检查累加溢出；
- 工作区大小、核半径和节点索引由实际模型及几何生成；
- 空间几何、空间核和弹药效果数据必须分离。

工作区在全部伤害和地形事件结算后才能清理。清理验证必须覆盖全部活动区域，而不是抽查首尾元素。

### 8.2 光栅化与视界算子

径向 DAG、局部窗口、射线复用和其他光栅化结构均为候选实现：

- 节点集合由核支持范围和几何生成；
- 索引类型必须覆盖实际节点数；
- 距离由核心几何计算；
- 只有真正共享射线前缀时才能声称精确复用；
- 遮挡、绕射和衰减系数必须归属具体模型；
- 近似必须给出误差与有效域。

### 8.3 地形变异

地形破坏必须通过事件产生：

```text
TerrainMutation → TerrainState Commit → Revision Increment → Dependent Cache Invalidation
```

局部重建可以只覆盖受影响区域及 Halo，但必须证明所有失效依赖均被标记。物理通行、导航、SDF、威胁与发布缓存不得继续使用旧修订。

### 8.4 守恒账本

人员、弹药、装备、补给和声明为守恒的物质必须满足：

```text
initial + legitimate_input = final + legitimate_output + accounted_transform
```

所有转移必须具有来源、去向、数量和事件原因。禁止双重扣除、凭空补货、匿名消失和饱和累加掩盖异常。

## 9. 确定性 Tick 事务

### 9.1 时钟

- Doctrine 默认原子 Subtick 为 **16 秒**，由唯一 `TickClock` 声明。
- 权威逻辑时间优先使用整数 Tick 或整数时间单位；浮点时间只用于显示或明确物理公式输入。
- 所有速率、冷却、装填和计划必须从该时钟推导，不得复制步长常量或使用含义不明的单位缩写。
- 修改 Subtick 必须重新验证所有时间相关模型、稳定性条件和调度语义。

### 9.2 三个逻辑状态

- $S^n$：Tick 开始时的已提交状态；
- $M^n$：运动提交后的 Tick 内中间状态；
- $S^{n+1}$：全部事件、持久状态与校验完成后的状态。

外部观察者在发布前只能看到 $S^n$，发布后只能看到完整的 $S^{n+1}$。

### 9.3 十三阶段管线

| 阶段 | 名称 | 必须完成的职责 |
| :--- | :--- | :--- |
| 0 | `BeginTick` | 固定输入修订，创建空工作区 |
| 1 | `ClockAndSchedule` | 推进逻辑时钟，提取到期命令与计划 |
| 2 | `PersistentFieldEvolve` | 推进声明为持久的环境场 |
| 3 | `DerivedRefresh` | 重建本阶段需要且有效的派生数据 |
| 4 | `SenseAndArbitrate` | 形成知识视图，仲裁全部意图 |
| 5 | `ProposeMotion` | 为每个有效运动意图生成提案 |
| 6 | `ConstrainMotion` | 执行路径、地形、容量和接触约束 |
| 7 | `CommitMotion` | 每实体至多一次位置提交，形成 $M^n$ |
| 8 | `EmitEvents` | 根据运动、武器和到期计划产生即时事件 |
| 9 | `ResolveEvents` | 稳定排序并产生唯一事件终态和效果 |
| 10 | `CommitPersistent` | 提交伤害、账本、地形和持久效果 |
| 11 | `Validate` | 检查合法性、守恒、修订和事件完整性 |
| 12 | `PublishAndDrop` | 形成 $S^{n+1}$、计算指纹、发布并销毁工作区 |

阶段内部可以并行，但不得跨越声明的数据依赖。不得为了沿用旧函数拓扑而增加第二条权威写入路径。

### 9.4 默认事件内部顺序

```text
DirectFire
→ DirectHit
→ BlastFieldBuild
→ BlastDamage
→ TerrainMutation
→ LedgerTransfer
→ PersistentEffect
```

模型需要不同顺序时，必须给出依赖证明，并保持稳定与可回放。

### 9.5 事务校验

发布前至少检查：

- 所有位置、生命、库存和物理场处于模型有效域；
- 所有即时事件均有唯一终态；
- 每实体至多一次位置提交；
- 所有持久效果恰好提交一次；
- 守恒账本平衡；
- 派生修订与权威依赖一致；
- 工作区清理范围完整；
- 快照、指纹和发布数据来自同一提交状态。

## 10. 确定性、存档与回放

### 10.1 完整权威指纹

指纹必须覆盖：

- 时钟、调度和随机状态；
- 地形及修订；
- 全部实体、关系、健康和姿态；
- 人员、弹药、装备和补给账本；
- 命令、权限和知识；
- 长期事件与装填计划；
- 持久环境场；
- 持久小数账本及其他权威连续状态。

只覆盖部分单位位置或地形修订的哈希不是完整世界指纹。

### 10.2 稳定执行

- 迭代顺序不得依赖无序容器遍历。
- 并行任务必须使用稳定分区和稳定归并，或证明结果与顺序无关。
- 随机流必须按稳定实体或事件键派生，不得依赖线程调度。
- 浮点结合顺序、近似数学和 SIMD 路径必须服从声明的确定性配置。
- 若提供严格逐位模式，所有优化都必须在相同输入上得到相同权威结果。

### 10.3 存档与回放

存档必须包含全部 `WorldState` 和重建派生状态所需的模型版本。回放必须使用相同输入命令、模型修订和确定性配置。派生缓存可以重建，但重建后不得改变权威指纹。

## 11. 算子与数值实现契约

### 11.1 统一算子接口

每个算子必须声明：

```text
Inputs / Outputs
Units
Preconditions
ValidityDomain
FailureModes
StateWrites
RevisionDependencies
DeterminismMode
ScalarReference
```

算子失败必须成为结果的一部分，不能只留下日志后继续提交。

### 11.2 标量参考实现

- 每个数值优化算子必须有语义清晰的标量参考实现。
- SIMD、定点、查表和近似实现必须与标量参考在声明容差内一致。
- 所有失败状态、边界行为和不可行结论必须一致，不能只比较正常路径。
- 标量参考是语义基准，不要求成为性能基准。

### 11.3 SIMD 与近似数学

AVX2/FMA 可以作为热点实现：

- 运行时必须检测硬件能力，并保留等价标量路径；
- 近似倒数、平方根和牛顿迭代必须验证误差上界；
- 禁止用近似掩盖零梯度、NaN、Inf 或无效输入；
- 权威累加溢出必须检查，禁止饱和后无声继续；
- 向量化不得改变稳定排序和事件归并顺序。

### 11.4 内存与缓存

- SoA、连续数组、Tile 和 Strip 是候选布局，不是物理语义。
- 外层结构体对齐不保证堆数组内容对齐，必须验证实际缓冲区地址和 Stride。
- `64 × 8` Strip 与 `64 × 64` Tile 可以作为与核心二进制几何配合的候选工作区；其实际采用必须由工作集和实测决定。
- Tile、Strip、Halo 和线程分区由实测工作集及硬件决定。
- 缓存命中率、微秒耗时和帧率只能作为特定机器上的测量结果，不能作为跨硬件正确性公理。
- 性能不足时只能改变实现参数或选择已声明的近似，不得削弱硬约束或删除结算。

推演核心按以下职责拆分：

```text
geometry       坐标、几何、索引与跨网格转换
state          权威状态、修订、账本和存档
fields         类型化场、生命周期和场算子
entities       实体、编制、库存与关系
intent         感知输入、意图候选与仲裁
motion         运动提案、约束和唯一提交
events         即时事件、稳定排序、终态和效果
operators      标量参考、SIMD 与有效域声明
transaction    时钟、阶段编排、校验和提交
publication    快照、指纹、脏区和发布
```

`SimWorld` 可以作为外观，但不得重新成为所有模块均可任意写入的巨石对象。跨模块写入必须经过明确事务接口。

Rust 是目标系统的唯一推演权威。其他语言可以用于测试、对照和工具，但不得形成第二套独立物理规则。

## 13. 服务端与前端边界

### 13.1 服务端

服务端只负责：

- 命令认证、权限和输入校验；
- 把外部请求转换为意图或计划；
- 提供快照、增量、指纹和诊断；
- 控制发布节奏与网络编码。

服务端不得复制碰撞、伤害、库存或任务场规则。

### 13.2 快照与增量

- 快照必须带世界 Tick、状态指纹和模型修订。
- 增量必须依赖明确基线，并支持基线失效后的完整恢复。
- 地形脏区、实体变化和聚合战斗表现必须来自同一已提交状态。
- 网络聚合可以压缩表现事件，但不得改变权威事件结算或丢失审计信息。

### 13.3 前端

前端只负责命令交互、可视化和音画表现：

- 不预测并回写权威伤害、库存或位置；
- 不把插值动画当作物理运动；
- 聚合弹幕、粒子效果和音频只是已提交事件的表现；
- 显示帧率不得反向改变逻辑 Subtick 或事件结果。

## 14. 验收红线

### 14.1 参数与几何

1. 所有核心战术几何均使用 Doctrine 规定的 `2^3 m` 格边长，场景和实现层不存在覆盖值。
2. 定点移位、浮点换算、连续坐标与网格索引往返符合声明规则，有符号坐标和越界输入显式处理。
3. 世界范围严格等于原点、行列数与核心格边长的计算结果；标准 `1024 × 1024` 配置必须得到 `8192 m × 8192 m`。
4. 面积、距离、核半径和邻域均由几何推导，不存在重复写死的派生常量。
5. 每个数值参数均可追溯到 Doctrine、场景、模型或实现配置及其修订。

### 14.2 状态与事务

6. 权威、派生和瞬态状态的所有权测试通过，瞬态清理不会删除任何持久状态。
7. 完整存档、加载和回放后的权威指纹一致。
8. 相同输入在重复运行及允许的同确定性并行配置下得到相同结果。
9. 每实体每 Tick 至多一个仲裁运动意图和一次位置提交。
10. 未通过校验的事务不能发布部分状态。
11. 所有即时事件具有且仅具有一个终态，无静默残留。

### 14.3 运动与硬约束

12. 高速运动测试覆盖整段路径，不能只验证终点无重叠。
13. SDF 陈旧、法向无效、非法初态和多重接触均产生明确失败或安全停止。
14. 信赖域只在全部前提成立时提供安全结论，缺失邻域时不得声称安全。
15. 容量预约在冲突下具有稳定结果，容量计数不被误当作连续接触证明。
16. 零梯度、不可达和陈旧任务场分别返回规定状态，不发生 epsilon 伪装或原始斥力回退。

### 14.4 场、事件与账本

17. `Sum` 沉积满足声明的守恒关系，其他代数使用各自正确性测试。
18. 场采样和事件结算不存在同一作用的重复伤害或重复转移。
19. 权威累加在溢出测试中显式失败，不发生饱和掩盖。
20. 地形提交使全部依赖缓存失效或重建，旧修订不能继续参与物理结算。
21. 人员、弹药、装备和补给在完整场景回放中满足守恒账本。
22. 瞬态工作区清理覆盖全部活动区域，长期事件、烟雾和持久小数保持连续。

### 14.5 双场与行为边界

23. 任务场共享仅在依赖键一致时发生，目标或模型不同的实体不会被错误合并。
24. 有限方向或局部视界近似具有误差和有效域测试，不冒充任意精确 LOS。
25. 物理内核不会仅因威胁阈值自行卧倒、撤退、切断任务或恢复意志。
26. 零方向矩具有明确的无朝向或记忆行为，相关状态被正确归档。

### 14.6 实现与系统

27. SIMD、定点和近似路径与标量参考在正常、边界和失败输入上符合契约。
28. 实际堆缓冲区对齐、Stride、越界和 Halo 均经运行时或测试验证。
29. 服务端与前端不存在第二套物理结算，快照和增量可从明确基线恢复。
30. 密集火力与大规模实体压力场景可复现，且报告完整输入、硬件、编译配置、线程数、内存和各阶段成本。
31. 性能未达标不会导致跳过事件、削弱硬约束、改变逻辑步长或丢失权威状态。

密集火力和大规模单兵场景是压力测试输入，不是无条件耗时或帧率承诺。任何性能门槛必须另附可复现环境。

## 15. 完成定义

只有同时满足以下条件，才能声称核心重构完成：

1. 核心 `2^3 m` 几何由 Doctrine 唯一声明，其余参数各归其主，不存在未经声明的全局常量。
2. 世界状态三分法落实，完整指纹覆盖全部权威状态。
3. 唯一 Tick 编排器控制全部权威提交。
4. 每实体唯一运动意图、唯一位置提交和完整路径约束生效。
5. 场、实体和事件的边界清晰，不存在身份丢失或双重结算。
6. 所有即时事件具有稳定顺序、唯一终态和可审计原因。
7. 守恒账本、地形修订和派生缓存失效形成闭环。
8. 双场只提供信息，硬约束只裁决合法性，行为模型独立拥有战术决策。
9. 标量参考、优化实现、服务端发布和前端表现服从同一世界契约。
10. 全部验收红线通过，性能结论具有完整可复现环境。

最终原则：
