下面这条路线以**每一步都可编译、可测试、可回退**为原则；不要先拆完所有结构体，也不要一开始做 SIMD。前面的步骤未通过验收，不进入下一步。

## 施工总顺序

```text
00 冻结行为基线
→ 01 建立 8 m 几何
→ 02 建立状态三分边界
→ 03 建立 TickClock 与事务骨架
→ 04 统一运动意图与位置提交
→ 05 建立即时事件缓冲与唯一终态
→ 06 打通一条火力竖切
→ 07 建立地形修订与缓存失效
→ 08 完整权威指纹与存档回放
→ 09 最小压力回归
→ 10 清理临时兼容路径
```

## 00. 冻结行为基线

### 施工

选一个足够小、但覆盖核心交互的固定场景：

- 两个兵种不同的实体；
- 一个直控实体、一个自主实体；
- 一处不可穿越障碍；
- 一次精确射击；
- 一次范围爆炸；
- 一次弹药消耗；
- 一次地形破坏；
- 一个跨 Tick 持久效果，例如烟雾或装填。

保存：

- 初始场景；
- 输入命令序列；
- 固定随机种子；
- 当前关键输出：位置、健康、弹药、地形和事件记录。

暂时不要追求所有输出完全一致；先区分：

- 重构中**不得变化**的语义；
- 已明确允许变化、需要更新期望值的语义。

### 验收

- 同一场景连续运行两次，现有系统结果能够复现。
- 测试能明确观察每次位置变化、伤害、弹药消耗和地形修改。
- 后续每一步都能重新运行这个场景。

**禁止：**没有基线就直接改主循环。

## 01. 建立唯一的 `2³ = 8 m` 几何

### 施工

在核心几何模块建立唯一 Doctrine 常量：

```rust
pub const TACTICAL_CELL_SIZE_M: f32 = 8.0;
pub const TACTICAL_CELL_SHIFT: u32 = 3;
```

建立 `GridGeometry`，至少包含：

- 原点；
- 行数、列数；
- 世界范围；
- 米制坐标到 `(r, c)` 的转换；
- `(r, c)` 到单元中心或边界的转换；
- 单元面积；
- 越界检查；
- 两点米制距离及核半径到单元支撑范围的换算。

如果采用定点坐标，再增加带 `F` 个小数位的移位实现；不要同时维护另一套隐式格边长。

这一阶段只让新代码依赖 `GridGeometry`，不要顺手重写所有地形算法。

### 验收

1. `1024 × 1024` 单元对应 `8192 m × 8192 m`。
2. 单元内点、单元边界、世界边界和越界点都有测试。
3. 负坐标不会通过无符号转换变成巨大索引。
4. 连续坐标 → 单元 → 单元坐标符合明确的舍入规则。
5. 距离、面积和核半径没有在其他模块再次写死 `8`。
6. 搜索核心代码，不存在另一个可替代它的权威 `cell_size`。

**停止条件：**不同模块仍可能对同一坐标得出不同单元。

## 02. 建立状态三分边界

### 施工

先建立三个逻辑容器，不要求立刻把所有字段完美拆完：

```text
WorldState
DerivedState
TickScratch
```

### `WorldState` 首先纳入

- 时钟；
- 地形；
- 实体；
- 弹药与装备账本；
- 命令与长期计划；
- 持久环境场；
- 随机状态。

### `DerivedState` 首先纳入

- 空间桶；
- SDF 与法向；
- AO、前线和门户缓存；
- 威胁场与任务场缓存；
- 渲染与网络缓存。

### `TickScratch` 首先纳入

- 意图候选；
- 运动提案；
- 即时事件；
- 瞬态杀伤场；
- 本 Tick 诊断。

每个派生缓存至少增加：

```text
dependencies
builder_version
validity
```

### 验收

- 任意字段都能回答：权威、派生，还是瞬态。
- 派生缓存销毁后，可以从权威状态重建。
- 瞬态工作区销毁后，没有应当跨 Tick 的信息随之消失。
- 烟雾、装填、长期事件和持久小数没有被当作垃圾清零。
- `WorldGrid` 不再被新代码当作“什么都能放”的默认位置。

**停止条件：**同一事实仍有两个可独立修改的权威副本。

## 03. 建立 `TickClock` 与事务骨架

### 施工

建立唯一 `TickClock`：

- 当前 Tick；
- 当前逻辑时间；
- 原子 Subtick 为 16 秒；
- 到期计划提取；
- 不允许其他模块自行推进时间。

把当前主循环包进十三个阶段骨架：

```text
BeginTick
ClockAndSchedule
PersistentFieldEvolve
DerivedRefresh
SenseAndArbitrate
ProposeMotion
ConstrainMotion
CommitMotion
EmitEvents
ResolveEvents
CommitPersistent
Validate
PublishAndDrop
```

最初允许阶段内部暂时调用旧函数，但每个旧函数必须归属唯一阶段。不要在这一步同时改变物理公式。

增加调试阶段轨迹：

```text
tick_id
phase
input_revision
event_count
diagnostic_count
```

### 验收

- 一个 Tick 内阶段顺序固定，不能跳过或重复执行。
- 所有速率只从 `TickClock` 获取步长。
- 没有第二个模块修改逻辑时间。
- 外部快照不会观察到半个 Tick 的中间状态。
- 基线场景在仅改变编排、不改变模型时保持预期行为。

**停止条件：**仍存在绕过事务骨架、由接口或定时器直接推进世界的路径。

## 04. 统一运动意图与唯一位置提交

这是第一处真正的语义改造。

### 施工顺序

1. 定义 `IntentCandidate`。
2. 定义仲裁后的 `MotionIntent`。
3. 定义 `MotionProposal`。
4. 定义 `ConstrainedMotion`。
5. 定义唯一 `MotionCommit`。
6. 直控只产生候选意图。
7. 自主系统只产生候选意图。
8. 仲裁器每实体最多保留一个意图。
9. 约束器只修改提案，不写实体位置。
10. `CommitMotion` 统一写位置。

删除当前“保存直控位置 → 运行自主 → 恢复位置 → 再执行直控”的竞争补丁。

约束按顺序接入：

```text
世界边界
→ 整段路径地形检查
→ SDF 修正
→ 容量预约
→ 实体接触约束
→ 最终合法性检查
```

先实现标量版本；遇到不可行就安全停止并返回原因，不要为了继续移动而穿透。

### 验收

- 每实体每 Tick 最多一个仲裁意图。
- 每实体每 Tick 最多一次位置提交。
- 同时存在直控和自主候选时，选择结果稳定且可解释。
- 自主系统单独运行时不能写位置。
- 高速提案不能只检查终点而越过薄障碍。
- 非法初态、负间隙、零梯度和无效法向不会触发假成功。
- 多实体竞争同一容量时，结果不依赖线程完成顺序。
- 基线中允许保持的运动结果保持一致；允许变化的结果有明确原因。

**停止条件：**任何战斗、动画或自主函数仍能直接修改实体坐标。

## 05. 建立即时事件缓冲与唯一终态

### 施工

在 `TickScratch` 建立统一 `EventBuffer`，事件至少包含：

```text
event_id
kind
resolve_phase
source_entity_id
target_key
model_revision
payload
stable_sequence
```

实现稳定排序：

```text
(resolve_phase, target_key, source_entity_id, source_event_id, sequence)
```

实现四个终态：

```text
Resolved
Rejected
DiscardedByRule
ConsumedByField
```

先迁移一种简单事件，例如装备移交或直接命中；不要一天内把所有事件类型塞进去。

`ShotPacket` 若继续存在，只能是即时事件载荷，不再是 `WorldGrid` 的长期字段。

### 验收

- 每个进入结算的事件恰好有一个终态。
- 每个终态都有原因代码。
- 相同事件集合无论并行生成顺序如何，最终排序一致。
-  Tick 末不存在未处理即时事件。
- 长期事件已转入权威调度，不依赖 `TickScratch` 存活。
- 被拒绝事件不会部分扣弹药、部分扣血或部分修改地形。

**停止条件：**队列清空仍被当作“事件已经正确处理”的证明。

## 06. 打通一条火力竖切

只选择**一种弹药、一次爆炸、一种地形效果**。

### 施工

打通：

```text
武器意图
→ 检查权限与库存
→ 生成射击事件
→ 消耗弹药
→ 构建瞬态超压/破片工作区
→ 实体采样并产生伤害
→ 产生地形修改
→ 提交账本、伤害与地形
→ 清理瞬态工作区
```

明确这条弹药的唯一结算方式：

- 若走精确事件，不重复采样场伤害；
- 若走聚合场，不重复执行旧直接伤害；
- 需要来源身份时，在场采样结算中保留来源事件 ID。

所有累加使用检查溢出的实现，禁止 `saturating_add` 隐藏问题。

### 验收

- 一发弹药只消耗一次。
- 一个爆炸只产生一次权威伤害结算。
- 同一目标不会因旧路径和事件路径受到两次伤害。
- 拒绝对零库存继续射击。
- 伤害来源能够追溯到射击者和事件。
- 瞬态场全部活动区域均被清理，不只检查首尾。
- 烟雾等持久效果不会被一起清理。
- 并行执行与标量串行执行结果一致。

**停止条件：**同一弹药仍有两条可能生效的权威结算路径。

## 07. 建立地形修订与缓存失效

### 施工

地形修改统一经过：

```text
TerrainMutation
→ TerrainState Commit
→ terrain_revision += 1
→ 标记受影响区域
→ 失效相关派生缓存
```

给 SDF、任务场、威胁场、空间桶及发布缓存记录依赖修订。局部重建必须包含受影响区域和必要 Halo。

### 验收

- 一次地形事务只产生规定的修订变化。
- 地形改变后，旧 SDF 不再参与运动约束。
- 地形改变后，旧任务场和威胁场不会被误认为有效。
- 未受影响缓存可以保留，受影响缓存没有漏标。
- 网络发布的地形与物理使用同一修订。
- 存档加载后能重建相同有效缓存，且权威结果不变。

**停止条件：**缓存只能靠“下次也许重建”保证正确。

## 08. 完整权威指纹与存档回放

### 施工

指纹覆盖：

- 时钟和调度；
- 地形及修订；
- 全部实体和关系；
- 健康、姿态和位置；
- 人员、弹药、装备和补给；
- 命令与知识；
- 长期事件和装填；
- 持久环境场；
- 随机状态；
- 持久小数账本。

明确序列化规则：

- 字段顺序；
- 整数编码；
- 浮点位模式或确定性数值规范；
- 集合排序；
- 规则集和模型版本。

派生缓存默认不进入指纹。

### 验收

1. 同状态重复计算指纹一致。
2. 修改任意权威字段，指纹都会变化。
3. 只重建派生缓存，指纹不变。
4. 存档 → 加载 → 继续运行，与未存档分支指纹一致。
5. 完整命令序列回放后，逐 Tick 指纹一致。
6. 并行配置不会改变指纹。
7. 网络快照的指纹与核心提交状态一致。

**停止条件：**仍存在“会影响未来世界、却不进入存档或指纹”的状态。

## 09. 最小压力回归

先保证正确，再测性能。

### 场景

- 多实体同时提出运动意图；
- 狭窄区域容量竞争；
- 高速跨格运动；
- 密集事件同时指向同一目标；
- 多次爆炸写入同一工作区；
- 连续地形破坏；
- 持久场与瞬态场同时存在；
- 多次存档、加载和回放。

### 验收

每次报告：

- 输入规模；
- 硬件与编译配置；
- 线程数；
- 峰值内存；
- 各 Tick 阶段耗时；
- 失败与拒绝事件数量；
- 最终指纹。

此步不设未经验证的毫秒或 FPS 红线，只建立后续优化基线。

**停止条件：**性能提升依赖跳过事件、放松约束或改变逻辑步长。

## 10. 清理临时兼容路径

只有前九步全部通过后才做。

### 施工

- 删除旧直接位置写入入口。
- 删除旧火力重复结算入口。
- 删除长期驻留在网格中的即时事件队列。
- 删除重复步长和重复格边长常量。
- 删除不再使用的保存/恢复位置补丁。
- 删除临时双指纹和双账本。
- 将含义不清的时间函数名统一为真实单位或 `subtick`。
- 最后再选择热点做 SIMD，不要求一开始 AVX2 化。

### 最终验收

- 全量测试通过。
- 基线场景通过。
- 逐 Tick 回放一致。
- 守恒账本平衡。
- 即时事件无残留。
- 持久状态无误清。
- 核心不存在第二条权威写入路径。
- 文档中的目标契约与代码实际行为一致。

## 你实际施工时的最小提交粒度

建议每一步再拆成三个独立提交：

```text
A. 新增类型与测试，不改变旧行为
B. 把一条调用链切换到新契约
C. 验收通过后删除旧路径
```

最重要的纪律是：**不要先建一大堆新结构体，却长期让旧系统继续写同一份状态。每迁移一条链，就关闭对应的旧写入口。**
