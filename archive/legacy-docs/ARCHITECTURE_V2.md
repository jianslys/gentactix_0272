# GenTactix V2 底层重构架构规格书（冷铁集团军群战役引擎）

> **文档定位**：供后续工程实施模型直接照此施工的底层架构与接口契约。  
> **核心准则**：物理规律确定性可复算；**严禁在底层代码中对“人性”做硬编码脚本**（例如禁止写死 `if org < 10: flee` 替指挥官与士兵做心理抉择）；零外部 API 依赖，全本地运行。

## 二、统一像素地形张量与微积分坡度场（`terrain_field.py`）

### 2.1 多通道栅格 `Grid[H, W]`
集团军群战区默认分辨率为 **`200 m/px`**（兼顾道路像素连通、河谷渡口与微积分坡度精度；大地图运算需采用 NumPy 向量化及局部 ROI 窗口更新以保证性能），每个像素 $(y, x)$ 包含以下通道：

| 通道名 | 类型 | 含义 |
| :--- | :--- | :--- |
| `elevation` | `float32` | 高程 $z$（米），支持真实 DEM 切片或架空地形导出矩阵 |
| `grad_x`, `grad_y` | `float32` | 3×3 Horn / Sobel 偏导 $\frac{\partial z}{\partial x}, \frac{\partial z}{\partial y}$ |
| `slope_deg` | `float32` | $\theta = \arctan\sqrt{g_x^2 + g_y^2}$（度） |
| `terrain_type` | `uint8` | 平原、森林、山地、沼泽、水域、城市、**铁路/干线公路/土路/桥梁/野战机场** |
| `weather` | `uint8` | 晴、雨、大雾、雪、泥泞、冰封（动态改写阻力与能见度） |
| `visibility_mod` | `float32` | 像素实时能见度修正（默认 `1.0`，受天气、**烟雾弹覆盖**、**夜间照明弹**动态修改） |
| `terrain_attrition` | `float32` | 非战斗地形损耗率（高寒冻伤、沼泽陷车、机械故障率） |

### 2.2 有向行军与道路优先级
1. **方向性坡度阻力**：部队按移动方向 $\vec{v}$ 行军时，通过点积 $\nabla z \cdot \vec{v}$ 区分上坡、下坡与等高线横切；上坡按坡度角 $\theta$ 放大机动阻力与油耗。
2. **绝壁禁行与道路覆盖**：无“道路属性”且 $\theta > \theta_{\max}$（如 $25^\circ$）的像素对轮式/装甲单位物理禁行；**道路属性像素（`rail` / `highway` / `dirt_road`）覆盖绝壁禁行限制**（允许盘山通行），但仍保留坡度油耗惩罚。桥梁/渡口被炸毁后退化为水域障碍。

## 三、“士兵去取”的实体化后勤与守恒不变量（`logistics.py`）

### 3.1 两段式补给配送模型
1. **段 1 · 道路像素链干线接力**：
   * 从后方补给点（铁路枢纽/兵站）出发，沿连通的**道路属性像素**向前推进；
   * 只要道路像素未被敌军占领或物理炸毁，干线输送仅计极低基础衰减，直达距离前线最近的**道路尽头像素**。
2. **段 2 · 道路尽头圆域辐射 + 士兵亲自去取**：
   * 补给不自动魔法送达阵地。以道路尽头像素为起算点，在设定的辐射圆范围内，前线单位必须派出人员往返搬运：
     * **运力分配**：优先使用编内的**运输/辎重班组**；运力不足时，必须从战斗班组抽调士兵充当搬运人力（直接按抽调比例降低本回合前线参战兵力密度）。
     * **像素里程衰减**：搬运队往返“道路尽头 ↔ 阵地”时，逐像素累加地形、坡度与泥泞阻力，决定实际送达率。
     * **中途截杀风险**：搬运路径经过敌方**炮兵弹幕区**或**制空低空扫射区**时，搬运队与运输车辆直接吃物理战损与物资截留。

### 3.2 测试比对验证不变量（Algorithmic Invariant）
* **质量守恒断言（仅用于算法单元测试比对，不强迫业务开局手动填复杂产能表）**：在单测沙盒中设定源头补给点总量 $S_0$，无论道路如何分支、辐射圆如何重叠、多少单位同时来取，所有单位实际收到的补给总量 $\sum S_{\text{delivered}} + \text{途损} \le S_0$，**严禁算法虚空算出多余补给**。

## 四、TO&E 树状编制（最小至班）、三账本与动态混编（`toe.py`）

### 4.1 四层编制树与班组三账本
* 地图棋子（军 / 师 / 旅 / 团 / 独立营）内部挂载树状编制：`作战群 → 营/连 → 排 → 班（Squad）`。
* 每个班组自带战术词条 Buff/Debuff（如工兵班提供架桥/排雷/抢修机场能力；重武器班提供高火力但拖累山地机动；侦察班扩大视野）。
* **每个班组拆分为 3 个独立账本**：
  1. `enlisted`（普通士兵数）
  2. `cadre`（军官与士官数）
  3. `equipment`（武器/火炮/车辆数，按型号记录）

### 4.2 残部复原与骨干（Cadre）约束
* **人装分离复原**：只要班组保留了核心 `equipment`，补充裸兵员即可在原地重新成建制。
* **骨干决定组织度恢复上限**：定义骨干保留率 $\text{Cadre\_Ratio} = \frac{\text{存活军官与士官}}{\text{满编军官与士官}}$。军官与士官基本健在时，补入新兵可迅速恢复组织度与战斗力；若军官/士官大量阵亡，即使补满新兵和装备，**组织度上限与恢复速率也被硬锁在低位**，需长期整训才能重塑骨干。

### 4.3 连以上总部动态混编（Kampfgruppe）
* 因为作战单位的战斗力、火力与机动完全由其下辖班组的 **`(equipment + enlisted + cadre)`** 动态聚合计算，无需绑定死板模板：
* **混编规则**：在回合结束阶段，任意一个**连级及以上总部（HQ）**均可框定周边有效集结半径内的残存士兵、闲置/散落装备与存活军官士官，**抽调合并生成一个新的混编编制（战斗群）**。混编后的属性与战斗力由新账本即时重算生效。

## 五、多维武器伤害矩阵与装备遗留（`combat.py`）

### 5.1 多维伤害类型
放弃“轻/重”二分法，建立伤害类型对不同目标的物理作用矩阵：

| 伤害类型 | 对暴露人员 (`enlisted`/`cadre`) | 对软装备/火炮 | 对装甲车辆 | 对组织度压制 | 特殊像素效应 |
| :--- | :---: | :---: | :---: | :---: | :--- |
| `small_arms`（轻武器） | 高 | 极低 | 无 | 中 | 无 |
| `he_blast`（高爆榴弹/航弹） | 极高 | 高 | 低~中 | 极高 | 破坏工事/道路 |
| `ap_kinetic`（穿甲动能） | 极低 | 低 | 极高 | 低 | 穿深判定 |
| `heat_shaped`（聚能破甲） | 中 | 中 | 极高 | 中 | 易引发车辆起火损毁 |
| `incendiary`（燃烧/白磷） | 高 | 中 | 低 | 极高 | 持续地形压制、逼出掩体 |
| `suppression`（纯震荡压制） | 极低 | 无 | 无 | 极高 | 压低敌方机动与射击效率 |

### 5.2 组织度压力与装备遗留判定
* **不设计人性脚本**：内核仅输出客观数值——当前组织度（0~100）、受压来源、退路封锁度、是否断粮。
* **装备遗留物理规则**：
  * 部队因**极低组织度**被迫后撤或溃散时，重武器/牵引火炮/抛锚车辆来不及撤收，按**班组自重系数 × (1 - 工兵抢修拖曳能力)**，大比例遗留在原像素格上；
  * 遗留装备写入该像素的 `abandoned_equipment` 槽位，后续占领该像素的部队可清点、破坏或缴获入编。

## 六、航空兵 1 小时 Sub-tick 与多弹种炮兵（`ww2_air.py`, `artillery.py`）

### 6.1 航空兵 1 小时级子循环（Sub-tick）
* 地面主回合（如 `6小时` 或 `1天`）内部嵌套 **1 小时步长的空中 Sub-tick 循环**。
* 航空兵挂载于**野战机场像素**，免疫地面地形减速，受限于机场作战半径与挂弹整备冷却：
  * **战斗机扫荡（Fighter Sweep）**：每小时结算空域争夺，裁出 `红方制空 / 蓝方制空 / 空域胶着`；夺取制空权后的富余战斗机转入低空扫射，压制无防空掩护纵队的机动并截杀取补给士兵；
  * **防空反制**：地面编有防空班组/高炮旅的空域，低空飞机每小时吃防空硬战损；
  * **空地协同（CAS）**：强击机/俯冲轰炸机在制空掩护下每小时执行波次打击，投掷 `he_blast` / `heat_shaped` / `ap_kinetic` 火力。

### 6.2 多弹种炮兵与像素环境改写
炮兵弹幕拦截不再只是扣血，而是按**弹药种类**结算：
* **高爆弹（HE）**：常规弹幕封锁，硬性压低穿过该区敌军的机动上限，结算 `he_blast` 物理损毁与组织度震荡；
* **反装甲弹（AP/HEAT）**：针对装甲集结区的高穿深打击；
* **烟雾弹（Smoke）**：**直接改写目标像素的 `visibility_mod` 属性**，生成临时烟幕遮蔽带，切断敌方炮兵观测哨、直瞄反坦克炮与空中俯冲轰炸机的瞄准线（掩护强渡与撤退）；
* **照明弹（Illumination）**：在夜间回合提升目标像素 `visibility_mod`，抵消夜战视野惩罚并暴露渗透单位。

## 七、信息与战争迷雾（`recon_fog.py`）

1. **多源侦察**：
   * 地面侦察半径受像素 `terrain_type`（森林/山地遮蔽）与 `visibility_mod`（天气/烟雾/夜战）实时压缩，受`侦察班`加成；
   * 空中照相侦察需在航空 Sub-tick 中突破或借制空掩护飞越敌后像素，带回精确编制与真假目标识别。
2. **无线电静默权衡**：
   * 开启静默的单位彻底隐匿电磁特征（不被敌方无线电测向捕获），但**脱离上级指挥链**：无法实时呼叫跨区炮兵弹幕与航空 CAS 支援。
3. **双层输出视图**：
   * `truth_state`（全图客观真值存档）与 `fog_view_red` / `fog_view_blue`（按各自侦察结果过滤后的虚实迷雾简报）。

## 八、测试验收红线（交接给实施模型的硬指标）

所有新增模块必须纯标准库 + NumPy（可选）离线可测，**不依赖 Streamlit 与任何外部 LLM API**，需配套以下验证用例：
1. **坡度微积分测试**：验证标准斜坡/山脊高程矩阵的偏导数、上坡/下坡有向阻力及道路覆盖绝壁禁行；
2. **后勤质量守恒测试**：验证多补给点、多分支道路、末端圆域抢补给场景下，绝对不出现“虚空造出多余补给”；
3. **TO&E 混编与人装分离测试**：验证轻武器/高爆伤害的装备损毁差异、低组织度重装备遗留、以及连级总部 `Kampfgruppe` 动态混编后战力重算；
4. **航空 1 小时 Sub-tick 与烟雾弹测试**：验证 6 小时主回合内 6 次空战 Sub-tick 推进，以及烟雾弹改写像素 `visibility_mod` 后对直瞄/空中瞄准线的实际切断效果。

## 九、V2.1 底层深化规约（像素容器、指挥链、作战区域与空域受令锁）

> 本章为面向后续工程重构的底层核心升级契约，严格遵循 **“零战术 AI 算法、纯物理与信息约束”** 原则。

### 9.1 像素静/动态分层与稀疏物资容器
1. **静态通道开局预烘焙**：
   * `200 m/px` 对应单个步兵班战术展开正面；高程、坡度（`grad_x`, `grad_y`, `slope_deg`）应在开局前采用更大尺度高程窗口一次性预烘焙写死，连同基础地貌、道路/铁路/桥梁属性作为静态底层。
   * 仅当战斗直接破坏地形（如炸毁桥梁、重炮破坏道路、建筑毁伤）时，事件触发局部改写静态通道；每回合主循环仅重算**天气、能见度（烟雾）、照明**三层动态场。
2. **任意像素皆可存补给与装备（稀疏像素仓库 `CellStash`）**：
   * 统一取消补给点与散落装备的割裂模型，底层为任意像素 `(r, c)` 提供稀疏物资/装备账本（非空才占用内存）；
   * 大型兵站、空投物资、撤退遗留重装备、前沿囤积弹药均视为像素自身存储的物资/装备；补给取用、缴获、卸货统一为“单位账本 ↔ 所在像素账本”的守恒转移。

### 9.2 地图最小下探至班、独立指挥官棋子与顺位继承
1. **最小实体下探至班（`Squad`）**：
   * 地图上可独立占格、机动与失联的最小作战实体下探至单个班（1 像素展开尺度）；营/连/排体现为编制树归属与指挥链拓扑。
2. **独立指挥官棋子（`Commander`）与不灭指挥链**：
   * 指挥官（如连长、连副、连军士长、排长）作为独立棋子或指挥节点存在，各自拥有坐标、通信设备与物理指挥覆盖半径。
   * **顺位继承**：只要某建制内仍存在至少一名存活军官或士官（`cadre`），指挥权不灭，按职级顺位自动递补代理（如 `连长 → 连副 → 连军士长`）；
   * **职级物理代差**：正职指挥半径最大且无额外传令延迟；副职或士官代理时，**物理覆盖半径缩小**、**可划作战区域配额缩水**、且**下达新命令附带额外传达延迟**。

### 9.3 纯 AO 指挥模型、延迟激活与断连归零
1. **指挥只通过画 AO 表达（废除老式点对点指令闸门）**：
   * 指挥官在底层不再逐个对单兵/单班下达点对点命令队列；指挥官在地图上划定/调整作战区域（AO，允许散落飞地），受**职级区块数量上限与总面积上限**约束（连长配额最高，连军士长显著更少）。
   * **AO 延迟激活**：正职划定 AO 当回合激活生效；副职/军士长代理或处于斩首震荡期时，新划 AO 需等待 `delay_turns` 回合后（`activate_turn`）方正式生效。
2. **唯一连通硬约束（断连即归零）**：
   * 单位须逐级连通直属上级指挥链（若班组与直属排断连，或脱离有效物理半径/无线电连通，即使身处排与连作战区域内也**一点连/排 AO Buff 都吃不到**）。
3. **层级作用分流与同级互斥**：
   * **排 / 连级 AO**：直接作用于连通的一线班组（组织度恢复与作战协同）；
   * **营级 AO**：不作用于班组，专用于**营属火炮瞄准/精度 Buff** 与 **侦察/战争迷雾 Buff**；
   * **团 / 旅 / 师级 AO**：不作用于班组，专用于**航空兵（机场整备冷却与空域 CAS/航拍效率）**与**战役后勤（运力提升与途损降低）**；
   * **同级互斥、跨级可叠**：**同一层级**的作战区域严禁重叠；**不同层级**（如连级与排级）重合时可各自独立计算并叠加。

### 9.4 航空兵空域驻留与空地协同无线电锁
1. **机场受令锁**：航空兵仅在**野战机场**或**机场无线电覆盖圈内**可接收任务指派（目标空域、任务类型、留空时长）。
2. **1 小时 Sub-tick 空域双判**：起飞进入目标空域后，每 1 小时同时结算对地影响（轰炸/扫射/照相侦察及防空战损）与自身空域状态（与重合空域敌机交战、留空时间消耗，任务完成或留空耗尽后下一小时直接返航）。
3. **空地协同破锁**：航空兵在空域驻留期间原则上不可中途改令；仅当目标空域下方存在具备**空地协同电台/引导编制**的友军单位时，方可实时转发新指令或改派空域。

### 9.5 像素暴露度加法场、开火残留、作战会议与斩首震荡
1. **单位暴露度与像素线性叠加（普遍物理法则）**：
   * 每个班组、指挥官与炮兵连自带基础暴露度（`base_exposure`）；每回合将全图所有单位的暴露度按所在像素**线性加法叠加**至 `Grid.exposure` 通道。
   * **开火 2 回合残留**：任意单位或炮兵连在本回合开火后，从**下一回合开始**在连续 **2 个回合**内额外增加暴露度，不同班组/兵种的增量不同（重炮/坦克/机枪远高于步枪班）。
   * 侦察与迷雾统一读取目标像素的最终 `Grid.exposure` 数值——同像素多单位重合、开火残留或踩入暴露区会线性推高像素暴露度，使敌方更远、更准地发现并锁定该像素。
2. **作战会议（War Council）与强制暴露范围**：
   * 高级指挥官与下级指挥官在 **`<= 1.0 km`（`5` 像素）** 内**连续停留在原地不动 $K$ 个回合**（默认 $2$ 回合），方可完成作战会议。
   * **动态同心双圈**：以两指挥官连线中点为圆心，**暴露范围**半径 `2.0 + 1.5 * min(1, dist_px/5)`（重合时最小半径 `2` 像素，相距 `1 km` 时直径 `7` 像素 = `1.4 km`），圈内全部像素及任何路过部队均强制叠加暴露度；**会议有效范围**半径 `max(0.5, dist_px/2)`（相距 `1 km` 时直径 `5` 像素 = `1.0 km`）。
   * **会议范围分流 Buff（外环暴露区不享受）**：仅会议有效范围内的友军吃独立新 Buff——**班组**强行直接加组织度（可突破 `org_cap()` 骨干上限）；**其他指挥官单位**放大其可划 AO 面积配额。
3. **高级指挥官伤亡斩首 Debuff**：
   * 高级指挥官一旦阵亡/失能，原作战会议协同 Buff 立即作废，下属指挥官与部队进入限时**斩首震荡期（`shock_ttl`）**，强吃组织度恢复受压与额外传令延迟。
