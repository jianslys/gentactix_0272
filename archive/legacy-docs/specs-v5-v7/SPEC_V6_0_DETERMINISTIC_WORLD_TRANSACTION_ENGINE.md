# Gentactix V6.0 确定性世界事务、双场与硬约束混合推演内核规格书

> **法典编号**：GTX-CORE-SPEC-V6.0  
> **文档状态**：架构提案；描述目标契约，不代表当前代码已经实现  
> **前序文档**：`SPEC_V5_0_CORE_DOCTRINE_DUAL_FIELD_AND_HARD_CONSTRAINT_ENGINE.md`  
> **适用范围**：`crates/gentactix-core`、`crates/gentactix-server`、`web/`，以及迁移期间的 Python 对照实现  
> **核心命题**：像素容器不是拥有战争意志的智能体，而是环境状态、守恒账本与派生场有效性的载体；实体保存身份与关系，事件执行精确结算，算子负责演化；整个世界只能通过确定性的 Tick 事务从 `S^n` 推进到 `S^(n+1)`。

## 0. 规范用语与对 V5 的继承关系

### 0.1 规范用语

- **必须（MUST）**：不满足即视为不符合本规格。
- **禁止（MUST NOT）**：不得以性能、兼容或演示效果为理由绕过。
- **应该（SHOULD）**：默认采用；偏离时必须记录理由与验证结果。
- **可以（MAY）**：可选实现，不构成正确性前提。
- **保证（GUARANTEE）**：仅在明确列出的前提全部成立时成立；前提失效时必须返回无效或不可行状态。

### 0.2 继承的核心方向

V6.0 继承 V5 的以下主干：

1. 欧拉空间场与拉格朗日实体混合建模。
2. 地形、容量与实体接触采用硬约束，而非仅依赖软斥力。
3. 长程任务导航与局部威胁信息分离，禁止为每个班组无条件构建独立全局场。
4. 单兵身份、编制、装备、伤病和物资继续由拉格朗日实体保存。
5. 固定原子 Subtick、分阶段推进、瞬态数据清理、SoA、局部计算与二进制脏区传输。
6. 密集火力允许以场聚合，但精确命中、装备移交和账本转移仍必须可结算、可审计。

### 0.3 收紧的无条件结论

以下说法不得再作为无条件工程承诺：

- 全战区固定为 5 m/px。
- 单次 SDF 投影或单遍逐对修正可以绝对杜绝所有穿透。
- 单元容量计数可以代替连续空间中的实体碰撞约束。
- 活跃任务场永远可以压缩到固定数量。
- 八方向输运场可以替代所有精确视线和精确命中查询。
- 保下降投影可以保证全局到达、严格防碰撞或自动形成战术包抄。
- 所有动态场和小数账本必须在每个 Subtick 末无条件清零。
- 固定缓存命中率、固定微秒耗时或固定 60 FPS 未经实测即可成立。

## 1. 目标、非目标与最高不变量

### 1.1 目标

1. **确定性**：同一权威初始状态、命令序列与配置，在支持的执行路径上产生相同权威结果。
2. **可复算**：每次状态变化都能归属到明确阶段、事件、实体或场算子。
3. **守恒**：人员、弹药、装备、补给和可守恒地形物质不得凭空产生或消失。
4. **物理可行**：地形不可穿越、实体接触和空间容量由独立约束系统执行。
5. **身份不丢失**：身份、来源、目标、顺序或指挥关系仍有意义时，不得提前场化。
6. **可渐进迁移**：不得要求一次性重写全部战斗、后勤、指挥和前端代码。
7. **可实测扩展**：优化以完整 Tick 成本、内存流量、依赖链和基准结果为依据。

### 1.2 非目标

- 不在底层写死“害怕、溃逃、卧倒、包抄”等心理或战术脚本。
- 不把双场解释为所有问题共用的唯一求解器。
- 不以连续密度合法性替代实体间最小间距合法性。
- 不在第一版同时实现所有连续介质、输运、MFG、DEC 或 GPU 算法。
- 不以视觉平滑、持续推进或帧率为理由破坏合法性与守恒。

### 1.3 冲突优先级

当约束互相冲突时，必须按以下顺序处理：

```text
世界有效性与守恒
  > 地形和实体硬约束
  > 命令权限与信息可见性
  > 任务进展
  > 运动平滑与视觉美观
```

若高优先级约束无法满足，系统必须停止相关提案、返回不可行原因，或将世界标记为无效并停止继续推进；禁止静默穿透、虚空补货或伪造成功。

### 1.4 禁止静默修复

- 禁止用随意增加的 `epsilon` 掩盖零梯度、不可达任务场或非法几何。
- 禁止把 `NaN`、负库存、非法实体位置直接 `clamp` 成表面合法值后继续运行。
- 物理模型自身明确规定的饱和函数可以使用上下限，但它属于本构模型，不得兼任错误修复器。
- 所有不可行结果必须携带机器可读的原因与相关实体、区域和阶段。

## 2. 世界状态的三分法

### 2.1 权威状态 `WorldState`

权威状态必须进入存档、回放和完整指纹：

| 分区 | 内容 |
| :--- | :--- |
| `ClockState` | Tick 序号、逻辑时间、计划任务时间 |
| `TerrainState` | 当前高程、材质、道路、桥梁、永久与半永久破坏 |
| `EntityState` | 单位、单兵、指挥官、编制关系、位置、速度、健康、装备与库存 |
| `CommandState` | AO 原始几何、命令、指挥链、延迟激活、正在执行的长期事件 |
| `KnowledgeState` | 各阵营观察记录、接触历史、置信度与知识时间 |
| `DynamicFieldState` | 需要跨 Tick 保存的烟雾、照明、暴露残留等动态场 |
| `SparseCellState` | `CellStash`、地面装备、尸体、雷区及其他像素实物账本 |
| `DeterministicRngState` | 若使用随机模型，保存确定性种子或计数器状态 |

### 2.2 派生状态 `DerivedState`

派生状态必须能够由权威状态重建，默认不进入权威指纹：

- 空间桶和实体邻域索引。
- AO 光栅化缓存与前线索引。
- SDF、法向、地形通行成本和掩体派生值。
- 门户图、导航场、LOS 共享前缀和威胁传播缓存。
- 渲染 Tile、网络压缩缓存和前端视图模型。

派生状态必须携带依赖修订号。依赖失效时不得继续作为有效真值使用。

### 2.3 瞬时状态 `TickScratch`

瞬时状态仅存在于一个 Tick 内：

- 仲裁后的单位意图。
- 运动提案与约束修正结果。
- `ShotPacket`、爆炸、命中、装备移交等即时事件缓冲。
- 瞬态超压、破片通量和本 Tick 伤害采样场。
- 脏区、事件序号、约束违规和写入日志。
- 临时求解器工作区。

Tick 结束后不得残留尚未明确持久化的瞬态事件或伤害场。具有明确跨 Tick 生命周期的烟雾、压制、疲劳和小数累计必须转入权威状态，不得借“清场”一并删除。

### 2.4 外观而非新巨石

`SimWorld` 可以继续作为服务器和测试的外观，但不得重新演化为包含所有实现细节的巨型对象。推荐逻辑结构为：

```text
SimWorld
├── state: WorldState
├── derived: DerivedState
└── systems: 无隐藏战争状态的算子集合

每个 Tick 的 TickScratch 由流水线局部创建，不作为长期世界事实保存。
```

## 3. 统一空间语义与多分辨率几何

### 3.1 连续世界坐标

1. 连续物理坐标统一使用米，记为 `(x_m, y_m)`。
2. 网格存储索引统一使用 `(r, c)`；`r` 对应 `y` 方向，`c` 对应 `x` 方向。
3. 经纬度、地图投影、屏幕坐标和前端 Canvas 坐标只能由适配层转换，不得进入物理算子。
4. 距离、速度、加速度、时间和面积必须在接口中体现单位或使用明确的强类型。

### 3.2 几何描述

语义接口如下，具体 Rust 类型名可在实施时调整：

```rust
pub struct GridGeometry {
    pub id: GeometryId,
    pub origin_m: [f64; 2],
    pub cell_size_m: [f64; 2],
    pub rows: usize,
    pub cols: usize,
}
```

给定世界点 `(x, y)`：

```text
c = floor((x - origin_x) / cell_size_x)
r = floor((y - origin_y) / cell_size_y)
```

越界点必须返回越界状态，不得默认 clamp 到边缘像素后继续当作真实位置。

### 3.3 多分辨率而非全场统一细网格

- 当前 200 m 战区网格可作为迁移父网格；新场景必须显式声明几何。
- V5 的 5 m 网格用于需要单兵几何、局部火力、战壕容量或精细 SDF 的 ROI。
- 从 200 m 降至 5 m，线性分辨率提高 40 倍，单通道单元数增加 1600 倍，因此禁止在整个大战区无条件复制 5 m 全通道世界。
- 子网格必须记录世界空间范围、父几何关系、有效掩码和生命周期。
- 跨分辨率采样必须显式调用转换接口，禁止仅凭相同 `(r, c)` 直接互读。

### 3.4 插值与沉积不是统一算法

- 平滑标量场的 `gather` 可以采用双线性插值。
- 不连续材质、合法掩码和障碍分类不得做模糊双线性插值。
- 守恒沉积必须保证核权重和总量关系；`max`、`Lp` 和 `min-plus` 通道不得套用线性质量守恒规则。
- 场梯度必须声明差分格式、边界条件和有效区域；不可达区梯度无效。

## 4. 类型化场契约

### 4.1 每个场必须具有的描述

```rust
pub struct FieldDescriptor {
    pub id: FieldId,
    pub geometry: GeometryId,
    pub physical_unit: PhysicalUnit,
    pub value_kind: FieldValueKind,
    pub aggregation: AggregationAlgebra,
    pub lifetime: FieldLifetime,
    pub authoritative: bool,
    pub validity: ValidityPolicy,
    pub dependencies: DependencySet,
}
```

首版应采用静态注册的明确场类型，不追求任意动态场脚本系统。新增场必须登记以上语义。

### 4.2 聚合代数属于物理语义

| 场类型 | 默认或候选代数 | 说明 |
| :--- | :--- | :--- |
| 人员/装备密度 | `Sum` | 必须满足相应质量或数量守恒 |
| 暴露度 | 按规约定义的 `Sum` 与衰减 | 多源暴露可线性叠加 |
| 烟雾光学厚度 | 通常为 `Sum` | 能见度由透射函数派生，不直接叠加能见度倍率 |
| 冲击波峰值 | `Max` 包络 | 同时或近同时冲击不直接线性相加峰值 |
| 多次冲击疲劳 | 经模型确认的 `Lp` 累积 | 必须说明 `p`、时间窗和衰减 |
| 破片通量 | `Sum` | 精确命中前仍须处理遮挡与空间分配 |
| 导航距离 | `MinPlus` | 通道关闭或代价增加时必须失效重算 |

不得因为底层都使用 `f32` 就统一执行加法。

### 4.3 场与实体的四个交换原语

- `deposit`：实体向场写入密度、暴露或其他可聚合量。
- `gather`：实体从有效场采样阻力、观测量或局部控制信息。
- `splat`：事件在允许放弃身份后聚合为场。
- `resolve`：事件对具体实体、像素账本或地形执行精确结算。

判断规则：**投影进场后若仍需知道“是谁、从哪里来、要打谁、按什么顺序”，就不得提前 `splat`。**

### 4.4 有效性与陈旧性

场查询结果必须能区分：

```text
Valid / OutsideBounds / OutsideRoi / InvalidMask / Stale / Unreachable / Degenerate
```

调用者不得把零值当作上述状态的通用替代品。

## 5. 实体、意图与离散事件

### 5.1 拉格朗日实体

以下信息必须保留在实体或明确的关系账本中：

- 全局身份、编制归属、指挥关系与阵营。
- 准确位置、姿态、碰撞体和移动能力。
- 人员、骨干、装备、弹药、背包、伤病与模块状态。
- 需要审计的命中来源、具体目标与装备移交关系。

密度场可以描述群体统计，但不能替代上述关系。

### 5.2 每实体每 Tick 唯一运动意图

玩家直控、自主决策、上级命令和事件锁不得分别写位置。它们必须先形成候选意图，再由仲裁器产生唯一结果：

```text
CommandIntent + AutonomyIntent + ActiveLocks
                  │
                  ▼
          Arbitrated MotionIntent
                  │
                  ▼
            MotionProposal
                  │
                  ▼
          Hard Constraint Result
```

仲裁器只解决意图来源与权限，不得绕过物理锁。禁止通过“先运行自主系统、再恢复直控单位旧位置”解决冲突。

### 5.3 事件缓冲不属于地形容器

`ShotPacket` 和其他即时事件必须存放在 `TickScratch.EventBuffer`，而不是作为 `WorldGrid` 的长期组成部分。

事件至少应具有：

```text
event_kind / tick / target_region / source_id / sequence / payload
```

消费顺序必须稳定。推荐排序键为：

```text
(resolve_phase, target_cell, source_entity_id, source_event_id, sequence)
```

哈希表只可用于索引，不得直接决定权威结算顺序。

### 5.4 迁移期火力事件

现有抽象 `fire_points` 与新的整数 `ShotPacket` 信息容量不同。迁移期间允许存在两类明确事件：

- `StrikeEvent::LegacyFirePoints`：保留旧结算语义。
- `StrikeEvent::ShotPacket`：保留弹种、发数、射手与优先目标等物理信息。

禁止为了形式统一而丢弃伤害类型、弹药来源或目标信息。旧入口只能在对应调用链完成等价验证后删除。

## 6. 确定性 Tick 世界事务

### 6.1 外部原子性

- 网络和其他外部读取者只能看到 Tick 边界上的已提交状态。
- Tick 内允许存在逻辑中间状态，但不得作为新回合事实发布。
- 不变量校验失败时不得继续发布正常结果；后续 Tick 必须停止，直到错误被显式处理。

### 6.2 标准阶段

| 阶段 | 主要工作 | 必须满足的边界 |
| :--- | :--- | :--- |
| 0. `BeginTick` | 创建空 `TickScratch`，冻结开始状态版本 | 不读取上一 Tick 的临时缓冲 |
| 1. `ClockAndSchedule` | 推进逻辑时钟，激活到期命令、AO 与长期事件 | 时间只由一个时钟源推进 |
| 2. `PersistentFieldEvolve` | 烟雾、照明、暴露等按生命周期衰减或扩散 | 只处理明确持久场，产生修订号 |
| 3. `DerivedRefresh` | 重建失效邻域、AO、SDF、导航与威胁缓存 | 陈旧缓存不得被读取 |
| 4. `SenseAndArbitrate` | 按阵营知识感知，仲裁玩家/自主/命令意图 | 禁止读取观察者无权获得的真值 |
| 5. `ProposeMotion` | 生成期望速度、位移和路径推进 | 不直接写最终实体位置 |
| 6. `ConstrainMotion` | 地形、容量、实体接触与位移约束 | 硬约束优先于任务进展 |
| 7. `EmitEvents` | 生成射击、爆炸、后勤、工程、移交等事件 | 不绕过事件缓冲直连伤害 |
| 8. `ResolveEvents` | 稳定排序，精确命中、伤害、账本与地形结算 | 每个事件至多按规约消费一次 |
| 9. `CommitAndInvalidate` | 提交持久效果，更新权威修订并失效派生缓存 | 不遗留不可见写入 |
| 10. `ValidateAndPublish` | 校验不变量、生成完整指纹和快照/脏区 | 失败世界不得继续正常运行 |
| 11. `DropScratch` | 清理即时事件和瞬态场 | 持久状态必须已显式写入 |

### 6.3 瞬态与持久残留

必须在 Tick 末清空的包括：

- 已消费即时事件。
- 仅用于本 Tick 的超压与破片采样工作区。
- 运动提案、临时邻域和临时排序数组。

不得无条件清空的包括：

- 仍有 TTL 的烟雾、照明和暴露残留。
- 规约明确跨 Tick 的小数伤亡、疲劳、装填或后勤累计。
- 未来才到期的命令、任务和长期事件。

### 6.4 时间调度

- 当前 Rust 内核的 16 s Subtick 应迁移为唯一 `TickClock` 定义，接口不得继续以 `5m` 暗示五分钟。
- 权威逻辑时间应优先使用整数 Tick 或整数毫秒，浮点小时仅用于显示和物理公式输入。
- 航空一小时循环、指挥节拍和装填计划必须依据累计逻辑时间或到期时间调度，禁止依赖与旧步长绑定的魔法取模数。
- 改变 Subtick 时长必须重新验证所有速率、冷却、采样和伤害模型，不能只修改一个常量。

## 7. 硬约束求解契约

### 7.1 约束系统不是像素容器自身的行为

像素和实体提供几何、容量、碰撞体与状态；独立约束算子输出：

```text
AcceptedProposal / CorrectedProposal / Blocked / InvalidInitialState / InvalidGeometry
```

每次修正必须保留原因和诊断信息。约束系统不得自行发明新任务目标。

### 7.2 地形 SDF 与连续路径

V5 的法向投影可作为局部修正算子：

```text
x ← x + (r_body - d(x)) n(x)
```

但必须满足：

1. SDF 与法向在查询点有效。
2. 对 `x_start → x_candidate` 的整段路径进行检查，不能只检查终点。
3. 高速移动必须采用扫掠体、保守推进或有证明边界的子步，防止隧穿。
4. 修正后仍需验证相邻几何、边界和其他硬约束。
5. 无效 SDF、不可信法向或无法收敛时必须停止提案或报告不可行。

因此，“四次乘加、单遍完成”不能作为全场景绝对无穿模证明。

### 7.3 实体间保守位移信赖域

对合法初态，可使用以下保守限幅作为无迭代安全子步：

```text
b_i = 1/2 × min_j(d_ij^n - D_hard - δ)
Δx_i = p_i × min(1, b_i / ||p_i||)
```

其安全保证仅在以下条件同时成立时适用：

- 初态已满足全部实体间距约束，`b_i >= 0`。
- 邻域集合包含本步所有可能接近的实体。
- 所有相关实体在同一线性子步内同步应用相同界限。
- 位移路径为受约束的直线子步，且没有未处理的外部位置写入。
- `||p_i|| = 0`、负间隙和非有限数均被单独处理。

该算子不保证任务进展、不修复非法初态，也不代替地形约束。非法初态必须进入独立、确定性的恢复流程，禁止静默传送。

### 7.4 容量与预约

- 单元容量必须来自明确物理模型，不得同时把容量计数当作连续碰撞证明。
- 实体进入有限容量区域时必须经过稳定顺序的预约或等效约束求解。
- 容量占用应由权威实体位置推导，或通过严格事务与位置同步提交，避免双账本漂移。
- 容量满时返回受阻；后续导航或局部绕流可以重新提案，但不得强制挤入。

### 7.5 约束组合

运动管线建议为：

```text
共享全局导航
  → 任务下降/局部修正
  → 速度和平滑限制
  → 地形连续路径约束
  → 实体邻域保守位移
  → 容量与最终合法性检查
```

任一后续修正都可能破坏先前软条件，因此最终只承诺硬约束与明确报告的软条件状态，不承诺所有中间数学性质仍自动成立。

## 8. 双场长程牵引与局部修正

### 8.1 任务场是共享导航数据，不是统一意志

任务场键至少应包含：

```text
goal_or_portal / mobility_profile / topology_revision / cost_revision / relevant_policy
```

- 相同键的实体必须共享导航结果。
- 活跃场数量由场景、拓扑和实测预算决定，不固定为 `J <= 8`。
- 可以使用门户图降低全局场数量，但门户图本身必须随桥梁、地形和通行关系变化失效。
- 局部威胁信息不得被宣称为恢复了全局绕障信息。

### 8.2 威胁与火力传播场

八方向输运、离散坐标法、卷积或共享 LOS 都可以作为候选算子，但必须声明：

- 空间与方向分辨率。
- 遮挡模型和近似误差。
- 源项、衰减和生命周期。
- 有效区域、置信度与修订依赖。
- 构建和更新成本，而不仅是单次查询成本。

精确武器射击、具体掩体判定和需要来源身份的伤害，仍可使用 DDA/LOS 与离散事件，不得被近似威胁场替代。

### 8.3 保下降半空间投影

令任务势为 `T`，`g = ∇T`，可行区域内基本任务速度为 `-v²g`。对局部修正向量 `w`，使用：

```text
q = ||g||²
b = v²q - ε_p
P_g(w) = w - ([gᵀw - b]₊ / q)g
u = P_g(w) - v²g
```

必须满足：

1. `q > 0` 且 `g`、`w`、`T` 均为有限有效值。
2. 半空间和速度约束在当前点可行。
3. `ε_p` 是模型明确规定的任务下降裕量，不得用于掩盖零梯度。
4. `q = 0`、不可达或陈旧场必须返回 `Degenerate/Unreachable/Stale`，由导航层重新求解或保持受阻。

该投影只保证其定义半空间内的局部下降关系与切向保留，不保证全局到达、不保证无碰撞，也不保证自动形成钳形包抄。

### 8.4 压制与意图分离

威胁场、暴露、组织度和火力压力可以产生物理修正与客观压力面板，但底层不得仅因单个阈值就强制：

- 转入卧倒并替代指挥决策。
- 永久切断任务意图。
- 自动撤退、自动包抄或恢复战斗意志。

姿态和任务变化必须由明确的意图/指挥规则提出，再由物理锁与硬约束裁决。若某产品模式需要自动行为，必须作为可替换策略层，而非物理定律。

## 9. 火力、毁伤与地形演化

### 9.1 两类结算路径

1. **精确事件路径**：子弹、穿甲弹、具体破片命中、装备移交、工兵消耗等，保留来源与目标并调用实体结算器。
2. **聚合场路径**：允许放弃个体身份的超压、破片通量、压制和区域风险，经 `splat` 后由实体 `gather`。

同一份物理效果不得同时通过两条路径重复结算。

### 9.2 密集火力

- 每发弹药必须遵守库存消耗与事件/场入账守恒。
- 聚合渲染包不等于聚合权威事件；后端仍需保存足够信息支持守恒与审计。
- 场化后的伤害采样必须处理空地、遮挡、实体截面和有效掩码。
- 小数累计是否跨 Tick 必须由具体模型规定，不得一概清零或一概保留。

### 9.3 地形破坏

- 地形变化通过离散地形事件提交，不得由渲染层直接修改。
- 受影响区域按实际算子支持半径与 Halo 计算；只有在证明 `3×3` 足够时才能固定使用 `3×3`。
- 材质、高程、SDF、通行成本、导航拓扑、LOS 和渲染修订必须同步失效。
- 若模型声称 crater 体积或质量守恒，则必须记录抛出物、填埋和残余体积；否则只能声明为经验形变模型。

## 10. 确定性、存档与指纹

### 10.1 稳定执行

- 实体、命令和事件使用稳定 ID 与稳定序号。
- 并行计算必须先产生与线程数无关的逻辑结果顺序，再按稳定顺序提交。
- 并行归约必须采用固定分块、固定顺序或其他可复现策略。
- 禁止依赖 `HashMap` 遍历顺序、内存地址、系统时间或未播种随机源。
- 随机模型必须使用可重放的确定性随机流，并记录种子与计数位置。

### 10.2 浮点与配置

- 目标平台、编译配置和浮点策略必须进入兼容性说明。
- 近似倒数平方根、FMA 重排和 SIMD 路径若可能改变结果，必须定义容差或固定为唯一权威执行路径。
- 不得声称未经跨线程数、跨运行和跨平台验证的逐位确定性。

### 10.3 完整权威指纹

指纹必须覆盖全部会影响未来推演的权威状态，包括但不限于：

- 时钟与 Tick。
- 当前地形和破坏状态。
- 实体位置、人员、装备、库存、健康、命令和长期事件。
- 指挥链、知识状态和确定性随机状态。
- 持久动态场和稀疏像素账本。

纯派生缓存与已清空的 `TickScratch` 不进入指纹。若只哈希部分单位状态，接口必须命名为部分指纹，不得称为完整世界指纹。

## 11. CPU、内存与性能验证

### 11.1 数据布局

- 热点实体和场优先采用 SoA 与连续存储。
- 64×64 Tile 可以作为存储、脏区和任务划分；64×8 滚动条带可以作为计算工作区。
- 工作集估算必须包括所有输入、输出、Halo、索引、临时数组和写回缓冲，不能只计算十个理想化通道。
- 稀疏 active 列表必须处理重复、删除和稳定顺序。

### 11.2 SIMD

- 第一正确性实现必须提供清晰标量路径。
- AVX2/FMA 只能在基准证明有效后引入，并提供运行时检测或不支持平台的构建方案。
- 禁止为使用 SIMD 而改变事件顺序、聚合代数或权威精度。
- 快速 `rsqrt` 等近似必须单独验证误差与确定性，不得默认替代精确运算。

### 11.3 必测场景

至少建立以下独立基准：

1. 大规模静态单位与少量活跃单位。
2. 大规模同时机动与邻域密集场景。
3. 5,000 发炮弹在一个 16 s Subtick 内集中结算。
4. 大面积烟雾、暴露与地形破坏导致的缓存失效。
5. 4096² 父网格与局部 5 m ROI 同时活跃。
6. 网络快照、脏区编码与前端上传成本。

报告必须区分：场构建、实体提案、约束、事件结算、提交、序列化和渲染成本。任何毫秒、缓存命中率或 FPS 结论都必须附硬件、编译配置、输入规模与原始测量结果。

## 12. 服务端、网络与前端边界

### 12.1 权威快照与增量

- 地形和动态场通过带 `geometry_id`、`revision`、Dirty Rect/Chunk 的二进制协议传输。
- 客户端必须能检测缺帧和修订断裂，并请求关键帧恢复。
- 实体权威事件与纯视觉聚合事件采用不同通道或明确类型。
- 炮击视觉聚合不得删除后端审计所需的实际弹药与结算数据。

### 12.2 信息权限

- 服务端只序列化观察者有权获得的知识视图。
- 自动策略、追击和前线情报同样不得读取无权获得的敌方真值。
- 派生威胁场若包含阵营知识，必须按阵营或知识域隔离。

### 12.3 前端职责

前端负责交互、可视化和音效，不参与权威物理提交。核心重构不得以简化内核为理由删除既有操炮、事件、背包或编制功能；UI 变更应另有产品规格。

## 14. 渐进迁移顺序与质量门

### 阶段 0：冻结语义基线

- 固化现有 `cargo test --workspace`、关键 Python 对照测试和基准场景。
- 明确 16 s 与历史 5 分钟接口的真实语义。
- 记录当前火力、机动、后勤和指纹行为，区分要保留的行为与明确要修复的错误。

**质量门**：基线可重复运行，失败项有清单，不以删除测试换取通过。

### 阶段 1：状态分类与事件边界

- 建立 `TickScratch`，把即时 `ShotPacket` 移出长期 `WorldGrid`。
- 明确 `WorldState/DerivedState/TickScratch` 清单。
- 扩充权威指纹与稳定事件排序。

**质量门**：同一事件不会重复或漏结算；不同哈希遍历和线程数不改变结果。

### 阶段 2：唯一意图与运动提交

- 合并直控和自主运动入口。
- 引入 `MotionProposal`、约束结果与不可行报告。
- 删除恢复直控单位旧位置的竞争写入补丁。

**质量门**：每实体每 Tick 只有一个位置提交者，硬约束失败可诊断。

### 阶段 3：场描述与修订失效

- 为烟雾、暴露、AO、导航和威胁场登记几何、代数、生命周期与依赖。
- 统一 Dirty Region 和缓存失效。

**质量门**：桥梁破坏、道路恢复、代价增加和 ROI 关闭均不会读取陈旧有效值。

### 阶段 4：端到端新管线竖切

只选择一条链路：

```text
一个班移动
  → 产生射击事件
  → 像素/ROI 接收并稳定排序
  → 结算实体与物资账本
  → 更新暴露或烟雾
  → 校验不变量并生成完整指纹
```

旧 `fire_points` 可暂存为独立事件类型；验证完成后才删除旧路径。

**质量门**：该链路全部经过新事务管线，无单位间绕过事件的隐式伤害。

### 阶段 5：局部精细几何与性能优化

- 在确有需求的 ROI 引入 5 m SDF、容量和单兵接触约束。
- 根据基准选择门户图、输运场、Tile/Strip、SIMD 和二进制优化。

**质量门**：优化前后语义一致，性能报告覆盖完整 Tick，不只覆盖微内核。

## 15. 验收测试红线

### 15.1 几何与场

1. 世界坐标与父子网格索引往返一致，越界和 ROI 外查询显式失败。
2. `Sum` 沉积满足守恒；`Max`、`Lp` 不被错误套用质量守恒断言。
3. 不连续材质和障碍掩码不被双线性插值污染。
4. 零梯度、不可达、无效 SDF 和陈旧场均返回对应状态。

### 15.2 运动与硬约束

5. 合法初态下，保守位移在声明条件内保持实体安全间距。
6. 高速跨格运动不能仅检查终点而穿过薄障碍。
7. 非法初态、负间隙和空位移不会触发除零、静默传送或假成功。
8. 多实体竞争有限容量时结果稳定，容量与位置账本不漂移。
9. 直控、自主和事件锁同时存在时只有一个运动提交结果。
10. 任务受阻时允许停滞并报告，不得为持续推进而穿透。

### 15.3 事件、战斗与守恒

11. 所有新管线火力必须经过事件缓冲，精确命中不被近似威胁场替代。
12. 同一爆炸不会同时走精确事件与聚合场造成双重伤害。
13. 多补给点、多单位领取、装备移交和地形遗留满足数量/质量守恒。
14. 瞬态超压与破片场在 Tick 末无残留；烟雾、装填和明确持久小数账本按规约保留。
15. 地形破坏同步失效 SDF、导航、LOS 与渲染缓存，包括“代价增加”场景。

### 15.4 确定性与信息边界

16. 相同输入重复运行、不同 Rayon 线程数和不同并行调度产生相同权威指纹。
17. 只改变弹药、长期事件、库存或持久烟雾也会改变完整世界指纹。
18. 无权观察者、追击策略和威胁场不能读取敌方真值。
19. Tick 校验失败后不会继续发布正常状态并推进下一 Tick。

### 15.5 性能

20. 5,000 发、50k 实体、4096² 父网格与局部 5 m ROI 均有可复现基准。
21. 性能报告包括内存、各阶段耗时、线程数与完整输入；微内核结果不得冒充整帧结果。

## 17. 完成定义

只有同时满足以下条件，才能宣称 V6.0 核心迁移完成：

1. 权威、派生和瞬时状态边界已落实，完整存档与指纹覆盖全部未来相关状态。
2. 所有实体位置与火力伤害均通过唯一、可审计的 Tick 管线提交。
3. 场、实体和事件不存在身份丢失、重复结算或绕过守恒的路径。
4. 硬约束的适用条件、不可行结果和非法初态处理均有实现与测试。
5. 所有派生缓存具有依赖修订，成本增加和拓扑恢复均能正确失效。
6. 新旧火力路径完成等价或明确差异验证，旧路径已删除而非永久并存。
