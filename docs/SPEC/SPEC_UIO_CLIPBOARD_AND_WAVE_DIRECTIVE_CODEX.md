# GenTactix 前端渲染分层、60天步长缓存与 UIO 手写板技术规格书

- **文档编号**：`GTX-SPEC-FRONTEND-UIO-STEPCACHE-V2`
- **适用范围**：`frontend/` 客户端渲染架构、步长缓存调度器、手写板（`UIO`）状态机及独立指挥面板（`Commander Wave UI`）。

---

## 1. 总体架构与前后端解耦工作流

### 1.1 前端逻辑先行准则 (Frontend-First Workflow)
1. **逻辑闭环优先**：前端交互、手写板队列状态机、时间轴宏拆解器、步长缓存与图层渲染管线由终端业务需求直接定义，**不因后端现有接口限制而在前端设计阶段妥协**。
2. **对接与演进顺序**：
   - 第一步：前端程序独立完成 `UIO` 状态机、本地步长缓存、宏拆解与 9 层渲染管线逻辑；
   - 第二步：对照后端引擎接口（`gentactix-server` / `gentactix-core`），后端已有接口能直接满足的直接对接；后端尚未支持的数据结构或能力，再定向扩展后端引擎。

### 1.2 逻辑网格隐形化与预渲染底图
1. **隐藏基础网格**：底层物理推演与空间索引采用 $8.0\text{m} \times 8.0\text{m}$ 二进制网格（`TACTICAL_CELL_SIZE_M = 8.0`），但该网格仅作为程序内部数学坐标与碰撞拾取基准，**对玩家视觉完全隐形（严禁在画面上渲染基础网格线）**。
2. **预渲染地图**：玩家看到的底图由前端美术预先烘焙/渲染为连续完整的地形画面，并通过严格的分层图层栈（Layer Stack）叠加动态战场要素。

## 2. 九层渲染管线与美术-程序隔离规范 (9-Layer Rendering Stack)

前端画面自底向上（`Z-Index: 1 -> 9`）严格划分为 9 个独立图层。前端程序仅负责向数据驱动层（Layer 2, 4, 5, 6, 8）投递结构化状态数据；前端美术独立掌控各层级的视觉材质、着色器与图元样式。**其中第 7 层与第 9 层必须支持玩家在运行时独立开启或关闭。**

| 图层编号 | 图层名称 | 核心渲染内容与职责边界 | 数据源 / 持久化归属 | 可否关闭 |
| :---: | :--- | :--- | :--- | :---: |
| **Layer 1** | **基础地图色彩层**<br>(Base Map Color) | 预渲染的连续地形基础色彩（地貌、道路、水系、等高底色），无网格线。 | 纯美术预渲染静态/分块纹理资产 | 否（常驻） |
| **Layer 2** | **地形破坏层**<br>(Terrain Destruction) | 弹坑、散兵坑、堑壕、爆破塌陷、焦土痕迹。置于 Layer 1 之上、Layer 3 (AO) 之下，以获得自然的明暗凹陷立体感。 | 步长状态中的地形改动与工事实例 | 否（常驻） |
| **Layer 3** | **环境光遮蔽色彩层**<br>(Ambient Occlusion) | 全局环境光遮蔽（AO）与地貌纵深明暗层，压在基础地图与地形破坏层之上，统一地表立体光影。 | 美术 AO 通道 + 局部地形法线/高程遮蔽 | 否（常驻） |
| **Layer 4** | **实例兵牌层**<br>(Entity & Tokens) | 所有战场拉格朗日实体：**作战单位兵牌、地面散落的物品（Items）、散落的武器（Weapons）、阵亡尸体（Corpses）**。 | 步长缓存插值轨线 + 迷雾裁剪状态 | 否（常驻） |
| **Layer 5** | **战术范围圈层**<br>(Range & Area Rings) | 直接指挥半径圈、无线电通联圈、射界扇区、测距圈；以及**点开顶栏指挥纸条时投射的波次炮击区、队友冲锋箭头与许可 AO 范围**。 | 选中态计算数据 + 顶栏激活的波次纸条数据 | 否（按需显隐） |
| **Layer 6** | **地图手绘辅助线层**<br>(Freehand Overlay) | 玩家在地图上自由绘制的辅助线、作战草图与标记。**100% 仅保存在客户端本地，绝不发送给后端，跨步长永久留存直至玩家主动擦除。** | 纯客户端本地存储 (`Memory + IndexedDB`) | 否（玩家自控） |
| **Layer 7** | **特效 A 层**<br>(World VFX A) | **天气（雨/雪/雾）、日照阴影、战场灯光（照明弹/探照灯）**。置于沙盘世界（Layer 1~6）之上、功能面板（Layer 8）之下，确保不遮挡 UI 面板文字。 | 环境状态驱动的着色器/粒子层 | **是（独立开关）** |
| **Layer 8** | **内置功能面板层**<br>(Functional HUD) | **手写板（`UIO`）、无线电台调谐面板**、单位检视器等核心交互控件。 | 前端 UI 状态机驱动 | 否（交互常驻） |
| **Layer 9** | **特效 B 层**<br>(Atmosphere VFX B) | **场景的气氛组**（桌面环境氛围滤镜、边缘暗角、震屏与全局环境颗粒）。置于最顶层（覆盖 Layer 8 之上）。 | 纯美术后处理/全局氛围层 | **是（独立开关）** |

## 3. 逐秒数值兑现机制与 60 天跨回合步长缓存 (Step Cache)

### 3.1 回合初预结算与 `1s..16s` 逐秒数值变化
1. **回合初账单锁定**：在每个 $16\text{s}$ 步长（Tick）开始时，该步长内第 `1s` 至第 `16s` 每一秒的数值如何变化（位移轨线、掉血减员、弹药消耗、压制增量、施工进度）已提前计算完毕。
2. **按秒渐进展示（防剧透穿帮）**：
   - 前端**严禁**在步长刚开始（`t = 0s`）就将第 `16s` 结束时的最终数值直接渲染给玩家；
   - 在 `1s..16s` 走表期间，前端根据当前走表秒数/毫秒戳（`exact_ms`），按秒驱动玩家可见的面板数值与 Layer 2/Layer 4 状态变化（连续量逐秒插值，离散爆破/命中伤害在到达触发秒拍时同步跳字扣减），走完 `16s` 时与回合末权威状态严格对齐。

### 3.2 跨回合超长步长缓存（60 天容量规格）
1. **设计目的（跨步长因果预知与零轮询触发）**：
   - 解决跨回合延期事件（例如：在 `#0` 回合已算好将在 `#4` 或 `#256` 回合于某坐标引爆的定时炸药、被时间混淆推迟的任务队列、延期生效的 $G$ 场波次）的存储与前向感知问题；
   - 当时间推演到 `#3` 回合时，系统通过直接读取步长缓存的下一槽位 `StepCache[#4]`，即可确知下一个回合（`#4`）该位置有炸药即将爆炸（或某指令即将生效），无需每回合全图遍历重算。
2. **容量上限与数据结构规格**：
   - **单步长时长**：$\Delta t = 16\text{ s}$；
   - **最大缓存跨度**：**`60 天`（$60 \times 86,400\text{ s} = 5,184,000\text{ s}$，共 `324,000` 个步长/Ticks）**；
   - **底层结构**：采用以目标回合号 `target_tick: u64`（有效范围 `current_tick + 1 ..= current_tick + 324_000`）为 Key 的稀疏步长桶（`BTreeMap<u64, StepCacheBucket>` / `Map<number, StepCacheBucket>`）：
     ```typescript
     export interface ScheduledStepEvent {
       eventId: string;
       sourceTick: number;       // 产生该预约事件的回合号（如 #0）
       targetTick: number;       // 预定生效的目标回合号（最大允许 sourceTick + 324000，即 60 天）
       secInTick: number;        // 1..=16 秒拍
       exactMs: number;          // 1..=16000 毫秒戳
       kind: 'detonation' | 'task_command' | 'g_field_wave' | 'macro_stop';
       subjectUnitId?: number;
       targetPos?: { x: number; y: number };
       payload: unknown;         // 原子指令、爆炸当量或波次 G 场参数
     }
     ```
   - **生命周期操作**：
     - **预埋（Schedule）**：在 `#0` 算出结果将在 `#k`（$k \le 324,000$）生效时，直接写入 `StepCache.get(k)`；空白回合不占内存；
     - **前向窥视（Lookahead）**：在 `#k - 1` 回合时，直接读取 `StepCache.get(k)` 获知下一回合即将触发的全部爆炸与变更；
     - **到期兑现（Drain & Execute）**：推进至 `#k` 回合交界时，一次性弹出 `StepCache.get(k)` 桶内所有事件送入结算与当拍 `1s..16s` 演出；
     - **中途注销（Cancel）**：若定时炸药在爆炸前被拆除或单位阵亡失联，按 `eventId` 从目标回合桶中定点移除。

## 4. 手写板（`UIO`）四区布局、无头指令与双重签发状态机

### 4.1 无头指令（Headless Directive）与前端拆宏
1. **无头指令结构**：玩家打开手写板时创建的初始对象为“无头指令”，包含：
   - **任务（Task）** 或 **事件（Event / 任务宏，即由多个基础任务按时序构成的复合动作序列）**；
   - **起止时间（`startTime`, `endTime`）** 及姿态、开火纪律等参数；
   - **待绑定槽位**：执行单位（`unitId`）与标的物（`target`，坐标/折线/多边形/目标单位）。
2. **延迟计算规则**：
   - 任一无头指令本身不计延迟，单位只要在队列中排到该时间点即刻执行；
   - 若需模拟指令延迟，直接对无头指令的起止时间施加乘数或偏移值，改写其时间轴起止刻度。
3. **前端宏展开职责**：
   - 前端手写板全权负责将“事件（任务宏）”与“起止时间”按时间轴拆解为一条条基础原子指令（如起始时刻发动作指令、阶段切换发后续指令、结束时刻自动发停止指令 `hold_unit`），写入步长缓存，当时间机扫到该确认指令的触发时刻才打包吐给后端。

### 4.2 手写板（`UIO`）四区架构与流转规则

#### (1) 顶栏：回形针指挥纸条栏（只读波次栏）
- **形态与来源**：手写板最顶部用回形针挂着一排只读的**指挥纸条**。该纸条不在手写板内创建，也不会签发任何无头指令到手写板上，而是由独立的【指挥 UI】签发生成。
- **无需对齐原则**：$G$ 场的指挥纸条主要用于驱动底层单位 AI 自己给自己签任务；玩家在手写板排任务队列时**无需对齐**顶栏的 $G$ 场纸条，玩家可按自身意图自由下令。
- **核心功能（波次投射与队友态势感知）**：
  1. 显示该指挥纸条对应的 **$G$ 场何时会真实生效在世界上**；
  2. 指挥纸条签发的不是单个队列，而是**“波次（Wave）”**。当玩家**点开顶栏任一上级指挥纸条**时，地图（Layer 5）直接显示出指挥官在该波次的部署：**指挥官打算炮击哪里（预定炮击区）、队友会往哪个地方冲（友军冲锋路线箭头）、队友被许可的 AO 范围（作战责任区边界）**，使玩家清晰掌握队友动向。

#### (2) 任务队列栏（Task Queue Lane）
- **准入死门禁**：任一无头指令在**未绑定标的物或未指定执行单位**时，严禁塞入任务队列栏，只能保存在草稿栏。
- **单单位时间槽互斥实时检测**：在手写板排队列阶段，前端实时校验同一单位在队列中的起止时间区间 $[T_{\text{start}}, T_{\text{end}}]$；一旦存在时间重叠，当场在手写板 UI 上高亮提示冲突，阻止违规排期。
- **双重签发机制（无头指令入列 $\neq$ 签发任务队列）**：
  - 单单签发无头指令放入任务队列，**绝对不会被后端执行**；
  - 玩家必须在任务队列栏排好顺序、检查完时序无冲突后，点击**【签发任务队列】**按钮；
  - 一旦点击【签发任务队列】，该队列正式锁死，**不可撤销**。
- **时间混淆与伪装异步帧**：
  - 玩家点下【签发任务队列】后，系统对队列执行确定性时间混淆（基于时间刻与单位哈希查表），**将任务队列拖延至下一个步长（`#1`）或下下个步长（`#2`）**写入步长缓存；
  - 只有当时间机扫到步长缓存中已确认指令的触发时刻，前端才将其吐给后端执行，从而避免回合制齐步走假象，实现伪装异步帧演出。

#### (3) 草稿栏（Draft Lane）
- 未绑定标的物或执行单位的无头指令必须保存在草稿栏；
- 草稿栏无限制：想放什么就放什么，**包括已经签发过的无头指令副本亦可存放在草稿栏中**作为模板复用。

#### (4) 归档栏（Archive Lane）
- 仅当任务指令**已经彻底执行完毕**后，才会自动从任务队列栏流转进入归档栏；
- **拖拽重用**：玩家可直接将归档栏中的历史纸条**重新拖回【任务队列栏】**，检查时序后再次点击【签发任务队列】重复执行。

## 5. 指挥官实体化、层级权限与独立【指挥 UI】

### 5.1 指挥官自身移动与直接/远程指挥偏移
1. **指挥官移动靠纸条**：玩家扮演的指挥官（班长/排长等）自身为战场实体，**指挥官自己如何移动，也必须通过手写板编写移动纸条、排入任务队列并签发来执行**。
2. **层级权限与远程指挥明牌偏移提示**：
   - **班长**：直接通过手写板操控本班组；
   - **排长（直接指挥）**：直接操控处于自身**直接指挥范围**内的直属班组；
   - **排长（远程指挥）**：当系统判定玩家在纸条上所选的执行单位**不在直接指挥范围内（属于远程指挥）**时，纸条 UI 上会直接计算并展示一个**偏移值**，以直白文案提示玩家**“该纸条因远程指挥可能会有延迟（+$X$ 秒/拍）”**。

### 5.2 独立的【指挥 UI】（Commander Wave UI）
1. **独立入口**：用于生成顶栏“指挥纸条”的操作不在手写板（`UIO`）内进行，而在另一个独立的**【指挥 UI】**中完成。
2. **波次图例绘制与 $G$ 场生效计算**：
   - 玩家在【指挥 UI】中于地图上绘制各类指挥图例（预定炮击区、推进箭头、许可 AO 区域等）；
   - 绘制完成后点击一次**“签发”**，即生成一整个作战**波次（Wave）**；
   - 系统在回合步长中同样按照**直接指挥**与**远程指挥**的通联条件，计算出该波次 **$G$ 场真实的生效时间**，写入 60 天步长缓存，并将对应的只读波次纸条挂上手写板（`UIO`）顶栏回形针区。

## 6. 第一阶段（前端独立逻辑闭环）施工与防糊弄验收死规矩

在正式连接后端引擎（`gentactix-server`）之前，前端工程（`frontend/`）必须先在**纯前端独立运行态**下完成 100% 的交互逻辑与状态机闭环，供人工实测验收。**严禁以“尚未连接后端”为借口交付无法点击、无状态流转或写死假数字的静态空壳！**

### 6.1 强制内置“本地模拟沙盒（Mock Sandbox）”与“本地 16s 走表器”
在未接真后端的第一阶段，前端必须内置一套完整的本地模拟数据源与本地步长走表驱动器，开箱即具备以下可交互测试场景：
1. **预置测试实体**：
   - 至少包含 1 个指挥官实体（排长）、2 个位于直接指挥范围内的直属班组、1 个位于直接指挥范围外的远程班组；
   - 地面预置散落物品、散落武器与阵亡尸体（用于验证 Layer 4 渲染）；
   - 手写板顶栏回形针区预置至少 2 张上级波次指挥纸条（含不同波次的预定炮击落区、友军冲锋箭头、友军许可 AO 范围及 $G$ 场生效时间）。
2. **必须可实机交互跑通的 7 项核心逻辑闭环**：
   - **门禁拦截实测**：新建无头指令（单任务或事件宏），在未完成“执行单位”与“标的物”绑定前，尝试拖入【任务队列栏】必须被拦截并仅允许存入【草稿栏】；
   - **远程指挥偏移实测**：绑定处于直接指挥范围外的远程班组时，纸条 UI 必须当场算出并用直白文案显示延迟偏移值；指挥官自身的移动同样只能通过编写并签发纸条驱动；
   - **单单位时间槽互斥实测**：在【任务队列栏】为同一单位排入两张起止时间重叠的纸条时，手写板必须实时高亮标红提示冲突，并锁定【签发任务队列】按钮；
   - **双重签发与时间混淆实测**：单张无头指令入列绝不触发执行；点击【签发任务队列】后队列当场锁死不可撤销，并通过时间混淆将其拖延至下一个步长（`#1`）或下下个步长（`#2`）写入 60 天步长缓存；
   - **60 天步长缓存与跨回合预知实测**：在 `#0` 回合预埋将在 `#4`（或任意 `#k`，最大支持 `#324000` 即 60 天）回合爆炸的定时炸药（或延迟事件）；当本地时钟推演至 `#3`（`#k-1`）回合时，系统必须通过读取 `StepCache[#4]` 明确识别并展示“下一回合即将爆炸”的前向状态，并在进入 `#4` 回合交界时准时触发爆炸；
   - **`1s..16s` 逐秒数值渐进变化实测**：本地 16s 时钟走表期间，单位位置、施工进度及受击掉血/弹耗必须严格按秒拍与 `exact_ms` 渐进变化，严禁在 `t = 0s` 提前剧透 `t = 16s` 的终局数值；
   - **归档流转与回炉重发实测**：指令执行完毕后自动从【任务队列栏】流转至【归档栏】；支持用鼠标将【归档栏】中的历史纸条重新拖回【任务队列栏】并再次签发执行。

### 6.2 九层物理容器隔离与持久化硬性验收
1. DOM / Canvas / WebGL 渲染树中必须真实建立 `Layer 1` 至 `Layer 9` 共 9 个按序堆叠的物理图层容器，**画面中严禁渲染底层的 8m 基础世界网格线**；

4. `Layer 7`（特效 A：天气/日照/灯光）与 `Layer 9`（特效 B：场景气氛组）必须配备真实可用的 UI 开关按钮，点击开关可实时切换该图层的显隐与渲染启停。

### 6.3 单一 `BackendAdapter` 接口层收口（为第二阶段连后端留好插座）

## 7. 后端 `gentactix-core` 同步改造规范：零 P2P 欧拉连续场结算与前后遮挡实扣

为彻底根除现有后端 `los_combat.rs` 与 `orchestrator.rs` 中“点名必中 P2P 扣血”、“`AttackPos` 打空地报 `MISSING_TARGET` 失效”以及“两人一前一后同时重复领伤”的物理缺陷，后端 `crates/gentactix-core/` 必须按以下三大核心法则进行改造：

### 7.1 彻底废除 P2P 伤害，全面采用“欧拉连续路径场/爆炸场 + 远近排队角度遮挡实扣”
1. **零 P2P 物理铁律**：
   - 任何武器开火（无论是选择敌方单位作为瞄准参考点，还是 `AttackPos` 向地面坐标射击）以及任何爆炸（炮弹、榴弹、地雷、定时炸药），**绝对不存在攻击者直接点名扣减单一目标血量的 P2P 绑定**。
2. **严格区分【直射子弹的路径杀伤场】与【爆炸物的爆心扩散场】**：
   - **直射子弹 / 穿甲弹（从枪口出发的锥形路径杀伤场，严禁做成瞄准点画圈扩散！）**：
     - 子弹是平射沿直线路径飞行的，不是从天上掉到瞄准点再往四周扩散的；
     - 精准度决定的是**枪口出膛时的散布夹角 $\Delta\theta$**（精准度越高夹角越窄，精准度越低或扫射时扇面夹角越宽）；
     - 子弹从枪口出发，沿着瞄准方向形成一条**贯穿整条弹道走廊的锥形路径场**（从枪口一路延伸，穿过瞄准点继续向后延伸至弹着远端危险区 Beaten Zone，直至撞上地形高程障碍或动能耗尽落地）；
     - 沿该路径距离枪口越远，角散布横截面越宽（单位宽度内的子弹密度越低），且子弹剩余动能随飞行距离持续衰减。
   - **高爆弹 / 地雷 / 定时炸药（以爆心为原点的径向扩散场）**：
     - 炮弹先确定实际起爆点（爆心），再由爆心向四周径向铺开破片通量场与冲击波超压场。
3. **沿路径从近到远排队与“半路截留 / 前后挡枪”角度遮挡实扣（单回合 5,000 次交火预算 $< 0.5\text{ ms}$）**：
   - **第一步（路径走廊粗筛）**：通过空间桶索引捞出所有处在**从枪口到弹道终点整条锥形路径走廊**（或爆炸半径）内的拉格朗日粒子（包括半路经过的单位、瞄准点处的单位、以及瞄准点后方弹道延长线上的单位）；
   - **第二步（按离枪口/爆心的距离从近到远排队）**：计算场内各粒子距离枪口（或爆心）的真实距离 $r_i$，严格按**从近到远（$r_1 \le r_2 \le \dots \le r_k$）**排序；
   - **第三步（前排半路截留 + 水平方位角 $[\theta_{\min}, \theta_{\max}]$ $\times$ 垂直高度斜率 $[s_{\text{low}}, s_{\text{high}}]$ 二维视窗遮挡实扣）**：
     - **严禁只按平面水平角度一刀切遮挡**（防止前排趴下或处于低洼处的矮单位把后方站立步兵或高大坦克完全挡死）；
     - 每个粒子根据其脚下地形高程 $z_{\text{base}}$ 与当前姿态身高 $h_{\text{posture}}$（如卧倒 `0.35m`、半蹲 `1.0m`、站立 `1.7m`、车辆 `2.5m`），相对枪口高度 $z_{\text{muzzle}}$ 与距离 $r_i$ 计算出**垂直高度斜率区间**：
       $$s_{\text{low}} = \frac{z_{\text{base}} - z_{\text{muzzle}}}{r_i}, \quad s_{\text{high}} = \frac{z_{\text{base}} + h_{\text{posture}} - z_{\text{muzzle}}}{r_i}$$
       与水平方位角 $[\theta_{\min}, \theta_{\max}]$ 共同构成该粒子的**二维迎弹视窗 $[\theta_{\min}, \theta_{\max}] \times [s_{\text{low}}, s_{\text{high}}]$**；
     - **前排截留与越顶射击**：沿路径离枪口更近的前排粒子 $1$ 仅截留并挡住落在其视窗 $[\theta_{1,\min}, \theta_{1,\max}] \times [s_{1,\text{low}}, s_{1,\text{high}}]$ 内的那部分子弹（撞击掩体与 `mm RHA` 等效装甲结算伤害，并将该视窗内的子弹从路径场中永久扣减销账）；**高于前排头顶斜率（$s > s_{1,\text{high}}$）的上半截子弹直接从前排头顶越过，分毫无损地继续沿路径向后飞行**；
     - **后排高出部分受弹**：排在后方（$r_2 > r_1$）的粒子 $2$ 若水平方向与前排重叠，其低于前排头顶（$s \le s_{1,\text{high}}$）的下半身被前排遮挡免伤（除非大口径穿甲弹打穿前排后残余动能过穿），但其**高于前排头顶、露在上方的一截视窗 $[ \max(s_{2,\text{low}}, s_{1,\text{high}}),\; s_{2,\text{high}} ]$** 仍完全暴露在越顶弹道中，照常按该露出截面的面积领走越顶飞来的子弹与剩余动能。

### 7.2 后端 `WorldState` 实装 60 天（`324,000` 步长）跨回合步长缓存 `StepCache`
1. 在 `WorldState` 中内建以目标回合号 `target_tick: u64`（最大支持 `current_tick + 324_000`，即 **60 天 / $5,184,000$ 秒**）为 Key 的稀疏步长缓存 `step_cache: BTreeMap<u64, Vec<ScheduledStepEvent>>`；
2. 凡在 `#0` 回合算好将在未来 `#k`（如 `#4` 或 `#256`）回合触发的定时炸药爆炸、经时间混淆推迟的任务队列原子指令、以及延期生效的波次 $G$ 场，一律直接写入 `step_cache[k]`；
3. 当推演至 `#k - 1` 回合（如 `#3`）时，`observe` / `/api/state` 可直接通过读取 `step_cache[k]`（如 `#4`）导出下一回合即将爆炸或生效的前向预警状态；当推演跨入 `#k` 回合 Stage 1/Stage 8 时，直接弹出 `step_cache[k]` 桶内事件送入欧拉连续场结算。

### 7.3 远程指挥由“一刀切拒单”改为“计算延迟偏移写入步长缓存”
1. 改造 `commands.rs::validate_tactical_command_access`：区分**直接指挥半径**与**远程指挥（超出直接指挥半径）**；
2. 当排长对超出直接指挥半径的单位下达指令时，不再返回 `OUT_OF_COMMAND_RADIUS` 粗暴拒单，而是根据距离与电台通联乘数 $\eta$ 计算出明确的延迟偏移拍数 $\Delta \text{ticks}$，返回给前端在手写板纸条上明牌提示，并将指令按偏移后的目标回合写入步长缓存。
