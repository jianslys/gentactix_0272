## Phase 01 · 权威 16s 整数时钟与三态容器对齐

### 1.1 修改文件
- `crates/gentactix-core/src/state/mod.rs`
- `crates/gentactix-core/src/sim_loop.rs`

### 1.2 具体施工步骤
1. **扶正 16s 无损整数时钟（铲除 `clock_hours: f32` 浮点累加）**：
   - 在 `SimWorld` 中新增字段：
     ```rust
     pub epoch_seconds: u64, // 默认 23400 (即 06:30:00)
     pub clock_seconds: u64, // 始终满足 epoch_seconds + (self.subtick as u64 * 16)
     ```
   - 在 `SimWorld::step_subtick_5m`（保留原函数名兼容调用，并新增别名函数 `pub fn step_subtick_16s(&mut self, driver: &mut dyn CommanderDriver) -> SubtickReport`）中：
     - 将 `self.subtick += 1;` 后的时间更新改为：
       ```rust
       self.clock_seconds = self.epoch_seconds + ((self.subtick as u64) << 4);
       self.clock_hours = (self.clock_seconds as f64 / 3600.0) as f32;
       ```
     - **严禁**再使用 `self.clock_hours += dt` 进行浮点累加！
   - 提供辅助格式化方法 `pub fn clock_hms_string(&self) -> String`，由 `self.clock_seconds % 86400` 精确格式化出 `"HH:MM:SS"`。
2. **在 `state/mod.rs` 中补齐四类修改的 `DerivedState` 结构定义**：
   - 在 `DerivedState` 中显式纳入四大缓存槽：
     - `planned_actions`: 存放班组/指挥班/重武器班组的移动、射击、隐蔽、停止、撤退任务队列与路径/LOS 预览缓存；
     - `planned_events`: 存放布雷、挖坑、建造、爆破、拆除、无线电、测距的读秒事件队列预览；
     - `immediate_staging`: 存放不走队列的拆分/整编编制、调整士兵装备、使用物品、架设/收拢重武器草案；
     - `command_fields`: 存放指挥 AO、进攻线、移动线、部署线及派生的欧拉连续场（$I, G$, SDF）。
3. **在 `TickScratch` 中补齐 $8\text{m}$ 网格杀伤寄存与事件变异槽**：
   - 确保 `TickScratch::reset_scratch()` 在每步结束时调用 `.clear()` 清空全部临时向量与哈希表，保持零堆内存重分配。

### 1.3 阶段验收命令
```powershell
cargo test --manifest-path "D:\tools\gentactix\Cargo.toml" -p gentactix-core
```
- **必过断言**：编写单元测试验证连续运行 225 个 16s 步长后，`clock_seconds` 精确增加 `3600` 秒，`clock_hms_string()` 从 `"06:30:00"` 精确变为 `"07:30:00"`，无任何 1 秒跳变误差。

## Phase 02 · $2^3 = 8\text{m}$ 网格杀伤寄存与场结算实装 (P2G $\rightarrow$ Field $\rightarrow$ G2P)

### 2.1 修改文件
- `crates/gentactix-core/src/combat_logistics.rs`
- `crates/gentactix-core/src/world_grid.rs`

### 2.2 具体施工步骤
1. **消除“假寄存、真遍历直接扣血”漏洞**：
   - 在 `combat_logistics.rs` 的 `resolve_cell_strike_ex` 中，**严禁绕过 `WorldGrid::pixel_containers`**！
   - 将伤害结算严格改为三拍流水线：
     - **第一拍（P2G 射弹注入 $8\text{m}$ 网格）**：构造 `ShotPacket`（含 `target_px`、`origin_px`、`ammo_spec_id`、`shots`、`incoming_dir_deg`、`remaining_radius_m`），调用 `grid.inject_shot_packet(packet)` 寄存进目标 $8\text{m}$ 网格的 `PixelCellContainer`；
     - **第二拍（Grid-to-Field 场展开与压制传递）**：从 `grid.pixel_containers` 读取寄存的 `ShotPacket`，计算目标格及高爆（HE）破片半径内邻近 $8\text{m}$ 网格的杀伤强度与压制密度 `suppression_density`，并写入网格压制状态与 `FireFields` 欧拉威胁场；
     - **第三拍（G2P 从受击 $8\text{m}$ 网格向驻留单位结算）**：仅针对受击 $8\text{m}$ 网格内的驻留单位，结合该格 `effective_cover_at(r, c)`、入射角夹角余弦 $\cos(\theta_i)$ 与步坦协同遮蔽结算人员伤亡、载具战损与组织度损失，结算完毕后消费并清空该网格已处理的 `incoming_packets`。

### 2.3 阶段验收命令
```powershell
cargo test --manifest-path "D:\tools\gentactix\Cargo.toml" -p gentactix-core
```
- **必过断言**：全部既有战斗测试通过，且验证射弹包经过 `pixel_containers` 寄存、更新 `suppression_density` 并在结算后清空。

## Phase 03 · 服务端 16s 脉冲单步 API 与状态导出

### 3.1 修改文件
- `crates/gentactix-server/src/main.rs`

### 3.2 具体施工步骤
1. **扩展 `/api/state` (`serialize_state`) 输出字段**：
   - 在返回的 JSON 根对象中显式加入：
     ```rust
     "tick": w.subtick,
     "clock_seconds": w.clock_seconds,
     "clock_str": w.clock_hms_string(),
     "step_seconds": 16,
     ```
2. **改造 `post_commit_turn` 支持整数单步 16s 脉冲**：
   - 在 `post_commit_turn` 中，优先读取请求体中的整数 `"subticks"`（或 `"step_count"`）：
     ```rust
     let subticks = body.get("subticks")
         .or_else(|| body.get("step_count"))
         .and_then(|v| v.as_u64())
         .map(|n| n.clamp(1, 225) as u32);
     ```
   - 若前端传入 `"subticks": 1`（或未传 `hours` / `turn_hours` 时默认按 `1` 个 16s 步长执行），直接精确运行 `subticks` 次 `step_subtick_16s`（先落盘本步附带的非队列编制/装备/无线电/战线调整，再执行 16s 步长推进），彻底避免用浮点 `hours` 折算步长！
   - 若旧测试显式传入 `"hours"` 或 `"turn_hours"` 且未传 `"subticks"`，则兼容按 `(hours * 225.0).round()` 执行，确保旧有 Server 契约测试不挂。

### 3.3 阶段验收命令
```powershell
cargo test --manifest-path "D:\tools\gentactix\Cargo.toml" -p gentactix-server
```
- **必过断言**：`test_v33_server_contracts_auth_and_estimate` 及新增的 `subticks: 1` 脉冲步进测试 100% PASS。

## Phase 05 · 前端 16s 双频计时器与 $2^n$ 倍速闭环

### 5.1 修改文件
- `web/index.html`

### 5.2 具体施工步骤
1. **$2^n$ 纯二进制倍速档位**：
   - 将 `#speed` 的点击切换逻辑从 `1 -> 5 -> 15 -> 1` 改为纯二进制序列：
     ```javascript
     const SPEED_STEPS = [1, 2, 4, 8, 16];
     ```
     点击 `#speed` 依次在 `1×`、`2×`、`4×`、`8×`、`16×` 之间循环切换。
2. **1s 现实时钟走表 + 16s 步长脉冲结算**：
   - 初始状态 `running = false`（暂停），`stepAccumulator = 0`（0 ~ 16 秒计数器）；
   - 删除底部原有的 `setInterval(fetchBackendState, 2500)` 无脑轮询（只在页面初始加载时调用一次 `fetchBackendState()`）；
   - 使用高精度计时循环（如 `250ms` 或基于 `performance.now()` 的 `requestAnimationFrame` / `setInterval`）：
     - 当 `running === true` 时，按当前倍速 `speed`（1, 2, 4, 8, 16）推进逻辑秒：每过 `1000 / speed` 毫秒，逻辑时间前进 `1` 秒：
       - `clockSeconds = (clockSeconds + 1) % 86400`，实时刷新右上角 `#clock`；
       - `stepAccumulator += 1`，实时刷新 `UI-18`（`#pulseStagingBar`）显示 `STEP ${String(stepAccumulator).padStart(2,'0')}/16S`；
     - **一旦 `stepAccumulator >= 16`**：
       - `stepAccumulator = 0`；
       - 立即触发一次异步步长结算 `await window.commitSimulationTurn()`（向 `POST /api/commit_turn` 发送 `{ subticks: 1, ...stagedPayloads }`）；
       - 用后端返回的最新权威 `state` 同步更新 `clockSeconds`、地图兵牌位置、接触线与左侧 `#inspector` 数据！
